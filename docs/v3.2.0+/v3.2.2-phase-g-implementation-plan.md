## 2. 模块设计（经 Codex 评估确认）

### 2.1 统一规范化（Clean）

**采用方案**: D（WeText ITN 预处理 + 两阶段清洗）

**设计理由**:
- **ITN 一致性**：快流和慢流都使用 WeText ITN，数字/日期/货币表示完全一致
- **简化对齐**：不再有 "10" vs "十" 的问题，`number_utils.py` 降级为兜底方案
- **语言覆盖**：WeText 支持 zh、en、ja、auto，覆盖主要使用场景
- **复用 Chunk 语言标签**：`chunk.language` 直接传给 WeText
- **分轨文本**：text_itn_raw 作为 raw 基准、text_clean 作为模型输入/对齐基准，避免与标点后处理冲突

**数据流设计**:

```
【快流】SenseVoice 原始输出（use_itn=True 保持）
    ↓
统一规范化层（WeText ITN → 安全标点标记 → 移除剩余标点）
    ↓
text_itn_raw + text_clean + char_mapping
    ↓
标点恢复：模型输入 text_clean → 候选标点
    ↓
后处理：raw_text=text_itn_raw + candidates → final_punct_text
    ↓
语义缓冲/Bridge 使用 final_punct_text（展示）
对齐/仲裁使用 text_clean

【慢流】Whisper 原始输出
    ↓
最小预清洗（Prompt 回显/极端重复/固定幻觉前缀）
    ↓
统一规范化层（同上）
    ↓
text_itn_raw + text_clean

【对齐】快流 text_clean ←→ 慢流 text_clean
    ↓
完美匹配！ "10" == "10"
```

**分轨文本定义**:
- `text_itn_raw`: ITN 后原文（保留标点），作为 raw_marks/后处理对比基准
- `text_clean`: 安全标点保留后的清洗文本（用于模型输入/对齐）
- `char_mapping/raw_to_clean/clean_to_raw`: raw 与 clean 的索引追溯

**核心算法**:

```python
from wetext import Normalizer
from dataclasses import dataclass
from typing import Dict, List, Optional

@dataclass
class NormalizationResult:
    """统一规范化结果（分轨文本）"""
    text_itn_raw: str
    text_clean: str
    char_mapping: List[CharMapping]
    raw_to_clean: List[Optional[int]]
    clean_to_raw: List[int]

class TextNormalizer:
    """统一规范化器（WeText ITN + 安全标点标记 + 清洗）"""

    def __init__(self):
        # 缓存各语言的 ITN 处理器
        self._itn_cache: Dict[str, Normalizer] = {}

    def _get_itn(self, lang: str) -> Normalizer:
        if lang not in self._itn_cache:
            # WeText 支持: zh, en, ja, auto
            wetext_lang = lang if lang in ("zh", "en", "ja") else "auto"
            self._itn_cache[lang] = Normalizer(
                lang=wetext_lang,
                operator="itn",
                enable_0_to_9=True  # 中文数字转阿拉伯数字
            )
        return self._itn_cache[lang]

    def normalize(self, text: str, lang: str) -> NormalizationResult:
        """统一规范化：ITN → 安全标点标记 → 清洗，输出分轨文本"""
        itn = self._get_itn(lang)
        text_itn_raw = itn.normalize(text)
        text_clean, mapping, raw_to_clean, clean_to_raw = self._clean_punctuation(
            text_itn_raw,
            lang,
        )
        return NormalizationResult(
            text_itn_raw=text_itn_raw,
            text_clean=text_clean,
            char_mapping=mapping,
            raw_to_clean=raw_to_clean,
            clean_to_raw=clean_to_raw,
        )

    def _clean_punctuation(
        self,
        text: str,
        lang: str
    ) -> Tuple[str, List[CharMapping], List[Optional[int]], List[int]]:
        safe_marks = mark_safe_punct(text, lang)
        clean_chars = []
        mapping = []
        raw_to_clean = []
        clean_to_raw = []
        for idx, ch in enumerate(text):
            if is_punct(ch) and idx not in safe_marks:
                mapping.append(CharMapping(raw_idx=idx, clean_idx=None, punct=ch))
                raw_to_clean.append(None)
                continue
            clean_chars.append(ch)
            mapping.append(CharMapping(raw_idx=idx, clean_idx=len(clean_chars) - 1))
            raw_to_clean.append(len(clean_chars) - 1)
            clean_to_raw.append(idx)
        return ''.join(clean_chars), mapping, raw_to_clean, clean_to_raw
```

**WeText ITN 效果示例**:

| 输入（口语） | 输出（书面） | 语言 |
|-------------|-------------|------|
| 一百二十三 | 123 | zh |
| 二零二六年一月 | 2026年1月 | zh |
| one hundred twenty three | 123 | en |
| 百二十三 | 123 | ja |

**安全标点规则表**:

| 语言 | 安全标点模式 |
|------|-------------|
| 通用 | 数字.数字（小数点：3.14） |
| en | 字母.字母（缩写：U.S.A）、字母-字母（连字符：self-driving） |
| zh | 无特殊规则 |
| ja | 中黑点（・） |

**边界情况处理**:
- WeText 不覆盖的边界情况由 `number_utils.py` 兜底
- 英文缩写(U.S.A.)与小数(3.14)需保留点
- 连字符需区分词内(-)与标点(—)

### 2.1.1 Bridge 语言切换刷新机制

**问题**: 当前 `BridgeBatch` 使用投票机制选择语言（`_select_language`），无法保证批次内语言纯度。混合语言批次会导致 WeText ITN 处理错误。

**解决方案**: 在 `BridgeController` 中增加语言切换检测，语言变化时强制刷新当前批次。

**设计理由**:
- **ITN 一致性**：每个 BridgeBatch 只包含单一语言，WeText 可使用正确的语言参数
- **对齐质量**：单语言批次避免跨语言对齐失败
- **最小改动**：仅在 `BridgeController.push()` 入口增加检测逻辑

**核心算法**:

```python
# bridge_controller.py - 语言切换刷新

class BridgeController:
    def __init__(self, ...):
        ...
        self._last_language: Optional[str] = None

    async def push(self, chunk: SemanticChunk) -> Optional[BridgeBatch]:
        # 语言切换检测（优先于其他刷新条件）
        language_flush_batch = self._flush_if_language_changed(chunk)
        if language_flush_batch:
            # 先输出已有批次，再处理当前 chunk
            self._queue.append(chunk)
            self._last_language = chunk.language
            return language_flush_batch

        # 正常入队逻辑
        self._queue.append(chunk)
        self._last_language = chunk.language or self._last_language
        ...

    def _flush_if_language_changed(self, chunk: SemanticChunk) -> Optional[BridgeBatch]:
        """检测语言切换，需要时刷新当前批次"""
        # 队列为空时不需要刷新
        if len(self._queue) == 0:
            return None

        # 缺少语言标签时跳过检测
        if not chunk.language or not self._last_language:
            return None

        # 语言相同时不刷新
        if chunk.language == self._last_language:
            return None

        # 语言切换：刷新当前批次
        return self._build_batch(flush_reason="language_change")
```

**验收标准**:
- [ ] 语言切换时自动刷新批次
- [ ] 刷新后的批次 `flush_reason` 为 `"language_change"`
- [ ] 新 chunk 进入新批次，语言标签正确
- [ ] 空队列时语言切换不触发刷新

**测试用例**:
```python
# 语言切换刷新
async def test_language_change_flush():
    controller = BridgeController(...)

    # 中文 chunk
    zh_chunk = SemanticChunk(text="你好", language="zh", ...)
    result1 = await controller.push(zh_chunk)
    assert result1 is None  # 首个 chunk 不刷新

    # 英文 chunk（语言切换）
    en_chunk = SemanticChunk(text="hello", language="en", ...)
    result2 = await controller.push(en_chunk)
    assert result2 is not None  # 触发刷新
    assert result2.flush_reason == "language_change"
    assert result2.language == "zh"  # 刷新的是之前的中文批次

# 同语言不刷新
async def test_same_language_no_flush():
    controller = BridgeController(...)
    zh1 = SemanticChunk(text="你好", language="zh", ...)
    zh2 = SemanticChunk(text="世界", language="zh", ...)

    await controller.push(zh1)
    result = await controller.push(zh2)
    assert result is None  # 同语言不触发刷新
```

### 2.2 仲裁算法

**采用方案**: C（多阶段渐进仲裁）+ 覆盖率与质量分混合判定

**设计理由**:
- 先排除慢流幻觉/长度异常，避免污染后续
- 覆盖率可反映对齐可用性，质量分反映内容可信度
- 最终决策符合"内容归Whisper、时间归SV"的原则

**核心算法**:

```python
class Arbiter:
    """多阶段渐进仲裁器"""

    def arbitrate(self, sv_result: SVResult, wh_result: WhisperResult) -> ArbitrationResult:
        # 阶段1：幻觉检测
        if self._detect_hallucination(wh_result):
            return ArbitrationResult(text_source="sv", reason="hallucination")

        # 阶段2：长度一致性检查
        if self._length_mismatch(sv_result, wh_result):
            return ArbitrationResult(text_source="sv", reason="length_mismatch")

        # 阶段3：对齐覆盖率计算
        coverage = self._compute_alignment_coverage(sv_result.clean, wh_result.clean)
        if coverage < 0.5:
            return ArbitrationResult(text_source="sv", reason="low_coverage")

        # 阶段4：质量分对比
        sv_score = self._score_sv(sv_result)   # 时间戳完整度、稳定性
        wh_score = self._score_wh(wh_result)   # 置信度、语义连贯性

        if wh_score >= sv_score * 0.9:
            # Whisper 质量足够，使用其文本
            if coverage >= 0.85:
                return ArbitrationResult(text_source="whisper", punct_source="merged")
            else:
                return ArbitrationResult(text_source="whisper", punct_source="sv")

        return ArbitrationResult(text_source="sv", reason="low_quality_wh")
```

**参数与阈值**:

| 参数 | 默认值 | 说明 |
|------|--------|------|
| coverage_high | 0.85 | 高覆盖率阈值，允许标点合并 |
| coverage_mid | 0.5 | 中覆盖率阈值，低于此回退 SV |
| len_ratio_min | 0.65 | 最小长度比例（Whisper/SV） |
| len_ratio_max | 3.0 | 最大长度比例 |
| quality_margin | 0.9 | 质量分边际系数 |

**边界情况处理**:
- Whisper 文本过长或过短的阈值需与历史对齐策略一致
- 慢流空输出直接回退 SV
- 多语言混杂时放宽长度一致性阈值

**文件位置**: `backend/app/services/arbitration/arbiter.py`

### 2.3 GapResolver 处理策略

**采用方案**: C（条件混合策略）

**设计理由**:
- 少量 gap 插值更平滑
- 中等 gap 合并可保持时间连续性
- 高 gap 降级避免伪时间戳污染

**核心算法**:

```python
def resolve_gaps(words: List[AlignedWord]) -> Tuple[List[AlignedWord], GapResolution]:
    """根据 gap 比例选择策略"""
    gap_ratio = count_missing_ts(words) / max(len(words), 1)

    if gap_ratio < 0.1:
        # Gap 少：线性插值
        return interpolate(words), GapResolution.INTERPOLATED

    if gap_ratio < 0.3:
        # Gap 中等：合并到邻词
        return merge_to_neighbors(words), GapResolution.MERGED

    # Gap 过多：标记降级
    return mark_degraded(words), GapResolution.DEGRADED
```

**参数与阈值**:

| 参数 | 默认值 | 说明 |
|------|--------|------|
| gap_ratio_low | 0.1 | 低 gap 比例阈值（插值） |
| gap_ratio_mid | 0.3 | 中 gap 比例阈值（合并） |
| min_valid_neighbors | 1 | 合并所需最小有效邻词数 |

**边界情况处理**:
- 首尾缺失时间戳需向内收敛或标记降级
- 连续多词无时间戳时，合并优于线性插值
- VAD 区间缺失时直接降级到 SV

**文件位置**: `backend/app/services/alignment/gap_resolver.py`

### 2.4 Whisper 文本清洗

**采用方案**: 最小清洗策略（复用现有 + 补充）

**设计理由**:
- 清洗优先级：默认优先复用当前已验证的慢流清理机制作为基础规则
- 最小干预：仅清洗明显的 Whisper 特有问题（Prompt 回显、重复片段、幻觉前缀）
- 保留原文：保留 `whisper_text_raw` 以便追溯和调试
- **优先复用旧代码**：复用 `text_normalizer.py` 的幻觉/重复检测与 `async_dual_pipeline._is_hallucination` 规则，必要时仅做适配
- **前端可更新词表**：新增字符串幻觉词表（短语/正则）可由前端维护，下次转录时注入清洗器并参与过滤

### 2.5 质量统计与监控

**采用方案**: 分层质量指标体系

**设计理由**:
- 为仲裁决策提供量化依据
- 为后续调优提供数据支持
- 监控对齐质量和 Gap 处理效果

**核心算法**:

```python
@dataclass
class QualityStats:
    """质量统计指标"""
    # 对齐质量
    coverage: float  # 对齐覆盖率 [0.0-1.0]
    alignment_score: float  # 对齐质量分数
    
    # Gap 统计
    gap_ratio: float  # Gap 比例
    gap_positions: List[int]  # Gap 聚集位置
    gap_resolution: str  # Gap 解决策略（interpolated/merged/degraded）
    
    # 文本质量
    sv_confidence: float  # SV 平均置信度
    wh_confidence: float  # Whisper 平均置信度
    repetition_ratio: float  # 重复比例
    
    # 仲裁决策
    text_source: str  # whisper/sv
    punct_source: str  # whisper/sv/merged
    arbitration_reason: str  # 决策原因

class QualityStatsCalculator:
    """质量统计计算器"""

    def compute_alignment_quality(
        self,
        sv_tokens: List[Token],
        wh_text: str,
        aligned_words: List[AlignedWord]
    ) -> QualityStats:
        """计算对齐质量指标"""
        # 1. 计算覆盖率
        coverage = self._compute_coverage(sv_tokens, aligned_words)
        
        # 2. 计算 Gap 比例
        gap_ratio = self._compute_gap_ratio(aligned_words)
        
        # 3. 计算对齐分数
        alignment_score = self._compute_alignment_score(aligned_words)
        
        # 4. 检测 Gap 聚集位置
        gap_positions = self._find_gap_clusters(aligned_words)
        
        return QualityStats(
            coverage=coverage,
            gap_ratio=gap_ratio,
            alignment_score=alignment_score,
            gap_positions=gap_positions,
            ...
        )

    def _compute_coverage(self, tokens: List[Token], aligned: List[AlignedWord]) -> float:
        """计算对齐覆盖率"""
        total_tokens = len(tokens)
        aligned_tokens = sum(1 for w in aligned if w.start is not None)
        return aligned_tokens / max(total_tokens, 1)

    def _compute_gap_ratio(self, aligned: List[AlignedWord]) -> float:
        """计算 Gap 比例"""
        total_words = len(aligned)
        gap_words = sum(1 for w in aligned if w.start is None)
        return gap_words / max(total_words, 1)
```

**指标定义**:

| 指标 | 范围 | 说明 |
|------|------|------|
| coverage | 0.0-1.0 | 对齐覆盖率，越高越好（期望 > 0.7） |
| gap_ratio | 0.0-1.0 | Gap 比例，越低越好（期望 < 0.2） |
| alignment_score | 0.0-1.0 | 综合对齐质量分数 |
| repetition_ratio | 0.0-1.0 | 文本重复比例（检测幻觉） |

**用途**:
- 仲裁决策依据（coverage、质量分）
- Gap 处理策略选择（gap_ratio）
- 性能监控和调优（分布统计）

### 2.6 语义注入层

**采用方案**: B（词边界标注模式）+ 嵌套标点支持

**设计理由**:
- 支持前置与后置标点，适配引号与括号
- 嵌套引号需要堆栈处理，否则易错位
- 不改时间戳，符合"标点只在对齐后注入"

**核心算法**:

```python
def inject_punctuation(
    aligned_words: List[AlignedWord],
    punct_positions: List[PuncPosition]
) -> List[AnnotatedWord]:
    """词边界标注模式，支持嵌套标点"""
    punct_map = build_boundary_map(punct_positions)
    stack = []  # 处理引号/括号嵌套
    result = []

    for i, w in enumerate(aligned_words):
        leading = punct_map.leading.get(w.char_start, [])
        trailing = punct_map.trailing.get(w.char_end, [])

        # 解析嵌套
        leading = resolve_nested(leading, stack)
        trailing = resolve_nested(trailing, stack)

        result.append(AnnotatedWord(
            word=w.word,
            start=w.start,
            end=w.end,
            leading_punct=leading,
            trailing_punct=trailing
        ))

    return result
```

**标点配对表**:

| 类型 | 配对符号 |
|------|---------|
| 中文引号 | ""、「」、『』 |
| 英文引号 | ""、'' |
| 括号 | （）、()、【】、《》 |

**边界情况处理**:
- 不成对引号：保留单侧标点并记录异常标记
- 连续标点(？！……)需作为序列保留顺序
- 词内安全标点不参与注入

### 2.7 最终切分层

**采用方案**: B（多因子联合切分）

**设计理由**:
- 可兼容"标点驱动"与"停顿驱动"两类场景
- 在无强标点时仍可用 VAD 与长度约束兜底
- 更易按语言与场景调参

**核心算法**:

```python
def split_final(
    words: List[AnnotatedWord],
    vad_pauses: List[VadPause]
) -> List[SentenceSegment]:
    """多因子联合切分"""
    scores = []

    for boundary in candidate_boundaries(words):
        punct_score = score_punct(boundary)       # 标点权重
        pause_score = score_pause(boundary, vad_pauses)  # 停顿权重
        length_penalty = score_length(boundary)   # 长度惩罚

        total = punct_score + pause_score - length_penalty
        scores.append((boundary, total))

    cuts = select_best_boundaries(scores)
    return build_segments(words, cuts)
```

**标点权重配置**:

| 标点类型 | 权重 | 说明 |
|----------|------|------|
| 强标点 | 1.0 | 。！？ |
| 弱标点 | 0.6 | ，；、 |
| 无标点 | 0.0 | - |

**参数与阈值**:

| 参数 | 默认值 | 说明 |
|------|--------|------|
| min_tokens | 5 | 最小词数 |
| max_tokens | 50 | 最大词数 |
| max_duration_s | 8.0 | 最大时长（秒） |
| pause_threshold_s | 0.35 | 停顿阈值（秒） |

class BridgeController:
    def __init__(self, ...):
        self._last_language: Optional[str] = None

    async def push(self, chunk: SemanticChunk) -> Optional[BridgeBatch]:
        # 语言切换检测（优先于其他刷新条件）

        self._last_language = chunk.language or self._last_language
        # ...正常入队逻辑

**可复用与不复用说明（sentence_splitter.py）**:

- **不复用（避免误判）**:
  - `ChineseStrategy/EnglishStrategy/JapaneseStrategy` 的语法完整性检查与不完整结尾词表
  - `_calculate_dynamic_pause_threshold()` 等 Layer 1 动态停顿逻辑
  - `_smart_split_long_sentence()` 的启发式拆分（可能与语义注入冲突）
- **原因**: 最终切分层基于“对齐后语义注入”的标点与停顿权重模型，语言穷举与 Layer 1 优化规则容易在定稿阶段误伤

```python
# final_splitter.py - 后处理平衡
def balance_segments(segments: List[SentenceSegment]) -> List[SentenceSegment]:
    """后处理：合并过短句，拆分过长句"""
    result = []
    for seg in segments:
        if len(seg.words) < MIN_TOKENS and result:
            # 过短句合并到前一句
            result[-1].merge(seg)
        elif len(seg.words) > MAX_TOKENS:
            # 过长句按弱标点或停顿拆分
            result.extend(split_by_weak_boundary(seg))
        else:
            result.append(seg)
    return result
```

## 4. 风险与验证建议

### 4.1 关键风险

| 风险 | 影响 | 缓解措施 |
|------|------|---------|
| 混合语言与缩写导致清洗误删 | 对齐失败 | 构建中英混排回归测试集 |
| 慢流幻觉未充分拦截 | 文本污染 | 多阶段幻觉检测 + 长度校验 |

| Gap 过多导致伪时间戳污染 | 时间轴漂移 | 条件降级策略 |

   - 中英混排文本（含缩写、小数）
   - 长句（> 50 词）

   - 定稿文本一致性（与人工标注对比）
