## 1. 概述

### 1.1 目标

本文档定义 V3.2.2 和 V3.2.3 两个版本的完整实施计划，实现：

1. **语言驱动的标点分句**：基于 LangID 路由选择分语言标点模型
2. **Bridge 层与慢流时序升级**：快慢流之间建立缓冲/调度/上下文管理
3. **折中标点调度层**：默认仅快流标点，异常触发慢流标点补跑
4. **标点驱动切分层**：定稿标点驱动字幕二次切分，字幕尽量不带标点
5. **测试验证途径**：提供临时输出接口验证标点重填结果

### 1.2 模型选择（最终确定）

| 语言 | 标点模型 | 运行时 | 量化 | 备注 |
|------|----------|--------|------|------|
| 中文 | WeTextProcessing (WFST) + FunASR CT-Transformer | ONNX Runtime | Int8 | WFST 负责逆文本标准化，CT-Transformer 负责标点恢复 |
| 英文 | Edge-Punct-Casing | ONNX Runtime | Int8 | 微软开源的轻量级标点模型 |
| 日文 | PunctCapSeg 47Lang (PCS-47Lang) | ONNX Runtime | Int8 | 多语标点恢复 |
| 兜底 | ASR 默认标点透传 | - | - | 快流优先，可配置为慢流优先 |

**WeTextProcessing 时间戳映射机制**：

WeTextProcessing 在中文逆文本标准化（ITN）中非常重要（如"一百二十三"→"123"），但会改变字符序列长度。为解决时间戳错位问题，设计以下映射机制：

```python
@dataclass
class TextNormalizationResult:
    """文本标准化结果"""
    original_text: str                    # 原始文本
    normalized_text: str                  # 标准化后文本
    char_mapping: List[CharMapping]       # 字符映射表

@dataclass
class CharMapping:
    """字符映射"""
    original_range: Tuple[int, int]       # 原始文本范围 [start, end)
    normalized_range: Tuple[int, int]     # 标准化后范围 [start, end)
    mapping_type: str                     # 映射类型: "identity" | "expand" | "collapse"
```

**映射规则**：
1. **identity**：字符不变，1:1 映射
2. **expand**：单字符扩展为多字符（如"①"→"1"），时间戳取原始字符
3. **collapse**：多字符折叠为少字符（如"一百二十三"→"123"），时间戳取原始范围的起止

**处理流程**：
```
原始文本 + 词级时间戳
    ↓
WeTextProcessing 标准化 + 生成 char_mapping
    ↓
CT-Transformer 标点恢复（基于标准化文本）
    ↓
通过 char_mapping 反向映射标点位置到原始文本
    ↓
输出带标点的原始文本 + 保持原始时间戳
```

### 1.2.1 标点 token 时间纠正（新增约束）

为避免标点占用时间导致时间戳错位，必须在清理标点前执行时间纠正：

1. **合并时间**：将标点 token 的时间合并到邻词（默认合并到前词；遇到左引号/左括号等前置标点时合并到后词）。
2. **删除标点 token**：合并后从 `word_timestamps` 中移除标点 token。
3. **禁止重算**：标点恢复完成后，**不得**基于“带标点文本”重算 `word_timestamps`，必须沿用纠正后的原始时间戳。

**实施阶段**：Phase B（FastWorker 标点集成），在调用 `PunctuationService.restore()` 之前执行。

### 1.2.2 快慢流标点调度策略（折中方案）

**默认策略**：仅快流执行标点模型；慢流标点按需触发。

**触发条件**（命中任一项即触发慢流标点补跑）：
1. 快流标点置信度低于阈值（例如 <0.55）
2. 对齐失败或覆盖率不足（锚点覆盖率/可对齐词比例过低）
3. 仲裁检测到异常（快/慢任一方疑似幻觉、冲突过大）
4. 任务配置或人工强制重跑

**调度层职责**：引入 `PunctuationScheduler`，统一管理：
- 根据运行模式判定是否允许慢流标点
- 记录触发原因与级别（便于日志与回放）
- 将调度决策附加到 `BridgeBatch` / `SlowWorkerResult` 供下游执行

**落点原则**：
- 标点只在仲裁阶段落一次（定稿），快/慢流仅产出候选位置
- 触发慢流标点时仅对慢流文本调用标点模型，不重算时间戳

### 1.2.3 兜底策略（ASR 默认标点）

**目标**：当标点模型不可用或被禁用时，直接使用 ASR 默认输出中的标点。

**优先级**：
- 默认优先快流（SenseVoice）
- 可通过配置切换为优先慢流（Whisper）

**边界说明**：
- 若 ASR 默认输出无标点，则回退 DefaultSegmenter 或保持无标点文本
- 兜底仅作为降级路径，不参与标点模型训练或重算时间戳

### 1.3 核心原则

1. **所有模型纳入统一模型管理系统**：通过 ModelManager V2 管理生命周期
2. **优先 ONNX Runtime**：CPU 推理优先，减少 GPU 竞争
3. **测试驱动**：每个阶段必须有充分的单元测试和集成测试
4. **可降级**：标点模型不可用时回退到 ASR 默认标点（可配置快/慢优先），必要时再回退 DefaultSegmenter
5. **双层可替换性**（贯穿全流程）：
   - **ASR 模型替换**：标点系统仅依赖 `ASRResult` 标准接口，换 ASR 模型只需适配输出格式
   - **标点模型替换**：所有标点模型通过 `PunctuationModelAdapter` 抽象层访问，换模型无需改业务代码
   - 数据结构（`PunctuationResult`、`SplitPoint`）保持稳定，上下游解耦

```
- **仅快流模式（sensevoice_only/fast_only）**：快流标点开启；慢流标点禁止；调度层仅记录异常，不触发补跑。
```

#### A.3.1 WeTextProcessing GIL 阻塞风险与线程卸载

**风险点**：WeTextProcessing 基于 WFST（加权有限状态转换器），底层虽是 C++，但在 Python 中执行时可能持有 GIL，阻塞 asyncio 事件循环。

**解决方案**：

1. **强制线程卸载**：
```python
# wetext_processor.py
async def process(self, text: str) -> TextNormalizationResult:
    """异步执行 ITN，避免阻塞事件循环"""
    loop = asyncio.get_event_loop()
    return await loop.run_in_executor(
        self._thread_pool,  # 专用线程池
        self._sync_process,
        text
    )
```

2. **预编译缓存**：
```python
def __init__(self):
    # FST 图只在初始化时编译一次
    self._fst_graph = self._compile_fst_rules()
    self._thread_pool = ThreadPoolExecutor(max_workers=2)
```

#### A.3.2 中文 ITN 与标点顺序验证（关键）

**风险点**：CT-Transformer 通常是在"非 ITN"文本上训练的（即"二零二三"而不是"2023"）。如果先做 ITN 把文本变成了"2023"，CT-Transformer 可能会因为没见过这种 token 而在数字周围乱加标点。

**验证步骤**（Phase A 必须完成）：

1. **训练数据分布验证**：
```python
# 验证脚本：scripts/verify_ct_transformer_itn.py
def verify_itn_compatibility():
    """验证 CT-Transformer 对 ITN 后文本的兼容性"""
    test_cases = [
        ("今天是二零二三年一月一日", "今天是2023年1月1日"),  # 数字 ITN
        ("我花了一百二十三块钱", "我花了123块钱"),           # 金额 ITN
        ("电话号码是一三八零零零零", "电话号码是13800000"),  # 电话 ITN
    ]

    for original, itn_result in test_cases:
        # 分别测试 ITN 前后的标点预测
        punct_before_itn = ct_transformer.predict(original)
        punct_after_itn = ct_transformer.predict(itn_result)

        # 比较标点位置是否合理
        validate_punctuation_positions(punct_before_itn, punct_after_itn)
```

2. **处理顺序决策矩阵**：

| CT-Transformer 训练数据 | 推荐顺序 | 说明 |
|------------------------|----------|------|
| 原始文本（"二零二三"） | 标点 → ITN | 先标点再归一化，避免 OOV |
| ITN 后文本（"2023"） | ITN → 标点 | 当前设计，需验证 |
| 混合训练 | ITN → 标点 | 最佳情况，当前设计可行 |

3. **兜底策略**：
```python
class ChinesePunctuationStrategy:
    def __init__(self, itn_first: bool = True):
        """
        itn_first: 是否先执行 ITN
        - True: ITN → 标点（默认，需验证 CT-Transformer 兼容性）
        - False: 标点 → ITN（保守策略，OOV 风险低）
        """
        self.itn_first = itn_first

    async def restore(self, text: str, ...) -> PunctuationResult:
        if self.itn_first:
            # 当前设计：ITN → 标点
            itn_result = await self.wetext.process(text)
            punct_result = await self.ct_transformer.predict(itn_result.normalized_text)
            return self._map_back_punctuation(punct_result, itn_result.char_mapping)
        else:
            # 保守策略：标点 → ITN
            punct_result = await self.ct_transformer.predict(text)
            itn_result = await self.wetext.process(punct_result.text)
            return self._adjust_split_points(punct_result, itn_result)
```

4. **配置开关**：
```yaml

  itn_first: true  # 可通过配置切换顺序
  fallback_on_oov: true  # OOV 时回退到保守策略
```

#### A.3.3 英文重叠窗口（Overlapping）策略

**风险点**：英文标点模型（如 Edge-Punct-Casing）对上下文敏感。如果每个 Chunk 独立推理，边界处可能因缺乏上下文而误判标点。

**解决方案**：重叠窗口策略，保留前一 Chunk 的尾部作为上下文。

```python
class EnglishPunctuationStrategy(PunctuationStrategy):
    def __init__(self, overlap_words: int = 10):
        """
        overlap_words: 重叠窗口大小（词数）
        """
        self.overlap_words = overlap_words
        self._prev_tail: Optional[str] = None

    async def restore(
        self,
        text: str,
        word_timestamps: List[WordTimestamp],
        context: Optional[str] = None
    ) -> PunctuationResult:
        # 1. 构建带上下文的输入
        if context:
            input_text = f"{context} {text}"
            context_len = len(context) + 1
        elif self._prev_tail:
            input_text = f"{self._prev_tail} {text}"
            context_len = len(self._prev_tail) + 1
        else:
            input_text = text
            context_len = 0

        # 2. 模型推理
        punct_result = await self.model.predict(input_text)

        # 3. 裁剪上下文部分，只保留当前 Chunk 的标点
        final_result = self._trim_context(punct_result, context_len)

        # 4. 更新尾部缓存
        self._prev_tail = self._extract_tail(text, self.overlap_words)

        return final_result

    def _extract_tail(self, text: str, word_count: int) -> str:
        """提取最后 N 个词作为下一次的上下文"""
        words = text.split()
        return " ".join(words[-word_count:]) if len(words) > word_count else text

    def reset_context(self):
        """说话人切换或长停顿时重置上下文"""
        self._prev_tail = None
```

### Phase B: FastWorker 标点集成 (预计 2-3 天)

#### B.0 兼容性检查点

**本阶段必须确保**：
1. `PunctuationService` 仅依赖 `PunctuationStrategy` 接口，不直接依赖具体模型

3. 标点模型失败时的降级路径不影响主流程

#### B.1 FastWorker 改造

**改造点**:
1. 在 SenseVoice 推理后执行标点 token 时间纠正（合并到邻词并删除标点 token）
2. 调用 PunctuationService 恢复标点（快流）
3. **统一后处理模块**：对 `PunctuationService` 的候选标点执行后处理（候选低分过滤 + 只增不删合并 + 置信度/句末/问号门控 + 候选一致性检测），输出 `final_text/final_positions`
4. 将后处理结果附加到 sv_result.metadata（保持句中标点）
5. 将快流标点置信度与质量特征交给 `PunctuationScheduler`，生成慢流标点请求（默认不触发）
6. 标点恢复后禁止基于带标点文本重算 `word_timestamps`
7. 支持标点模型不可用时的降级

**伪代码流程**:
```python
async def process(self, chunk: AudioChunk) -> FastWorkerResult:
    # 1. SenseVoice 推理
    sv_result = await self.engine.transcribe(chunk.audio)

    # 2. 标点 token 时间纠正（合并到邻词并删除标点 token）
    sv_result.words = merge_punctuation_tokens(sv_result.words)

    # 3. 标点恢复（新增）
    if self.punctuation_service:
        try:
            punct_result = await self.punctuation_service.restore(
                text=sv_result.text,
                language=chunk.language,
                word_timestamps=sv_result.words
            )
            # 3.1 统一后处理（快流模式）
            post = postprocess_punctuation(
                raw_text=sv_result.text,
                words=sv_result.words,
                language=chunk.language,
                mode="fast",
                candidates=punct_result.punctuation_positions,
                config=punct_postprocess_config,
            )
            sv_result.metadata["punctuation"] = post
            # 3.1 调度决策（默认只快流）
            decision = self.punctuation_scheduler.evaluate_fast(
                punct_result=punct_result,
                sv_confidence=sv_result.metadata.get("display_confidence")
            )
            sv_result.metadata["punctuation_decision"] = decision
        except PunctuationError as e:
            logger.warning(f"标点恢复失败，降级到无标点: {e}")
            sv_result.metadata["punctuation"] = None
            sv_result.metadata["punctuation_decision"] = PunctuationDecision.skip(
                reason="punctuation_error"
            )

    # 4. 注意：标点恢复后禁止基于带标点文本重算 word_timestamps

    return FastWorkerResult(sv_result=sv_result, chunk=chunk)
```

#### E.1.1 背压机制详细设计（关键）

**风险点**：如果 FastWorker 生成速度远超 SlowWorker 消费速度，Bridge 队列会无限膨胀，导致 OOM 或极高延迟。

**解决方案**：

1. **有界队列**：
```python
class SentenceQueue:
    def __init__(self, maxsize: int = 50):
        self._queue = asyncio.Queue(maxsize=maxsize)  # 有界队列
        self._backpressure_event = asyncio.Event()
```

2. **流量控制信号**：
```python
async def push_segment(self, segment: SentenceSegment) -> bool:
    """阻塞式 push，实现背压。返回 False 表示需要暂停上游"""
    try:
        await asyncio.wait_for(
            self._queue.put(segment),
            timeout=self.backpressure_timeout  # 默认 5s
        )
        return True
    except asyncio.TimeoutError:
        # 队列满载超时，向 FastWorker 发送暂停信号
        self._backpressure_event.set()
        return False
```

3. **FastWorker 响应背压**：
```python
# 在 FastWorker 推理循环中检查背压信号
if bridge.is_backpressure_active():
    await bridge.wait_for_capacity()  # 等待队列有空间
```

4. **丢帧策略（兜底，可选）**：
```python
# 直播场景下的紧急丢弃策略
if self.enable_frame_drop and self._queue.full():
    dropped = self._drop_oldest_non_boundary()
    logger.warning(f"背压丢帧: dropped={dropped}")
```

**配置参数**：
| 参数 | 默认值 | 说明 |
|------|--------|------|
| queue_maxsize | 50 | 句子队列最大容量 |
| backpressure_timeout | 5.0s | 背压等待超时 |
| enable_frame_drop | False | 是否启用紧急丢帧（直播场景） |

```
ArbitrationResult
├─ final_sentences (仲裁后的句子列表)
├─ confidence_score (仲裁置信度)
└─ arbitration_details (仲裁详情)
        ↓
if confidence_score < 0.6 and not slow_punct_rerun:
    → 触发慢流标点补跑并重试仲裁一次
elif confidence_score < 0.6:
    → 回退到纯 SenseVoice 结果（保守策略）
else:
    → 采用仲裁结果
        ↓
    统一后处理（mode=dual，候选过滤 + 只增不删 + 置信度/句末/问号门控）
        ↓
    PunctuationDrivenSplitter.split(...)  # 标点驱动切分层
        ↓
    定稿推送
```

#### G.5 慢流标点补跑触发（调度层）

**触发条件**（仲裁阶段复核）：
1. 关键锚点对齐失败（覆盖率/一致性低于阈值）
2. 仲裁检测到幻觉或冲突过大（任一方异常）
3. 快流标点置信度已低且仲裁结果不稳定

**执行策略**：
- 仅允许一次慢流标点补跑（避免反复重算）
- 补跑仅对慢流文本调用标点模型，不触及时间戳
- 补跑完成后立即重试仲裁，仍失败则回退快流

#### G.6 标点驱动切分层（推送前）

**目标**：使用“定稿标点”驱动字幕切分，让每条字幕尽量不带标点，同时保持原始时间戳不变。

**输入**：
- `ArbitrationResult.final_sentences`（带定稿标点）
- `SentenceSegment.words`（已纠正后的词级时间戳，无标点 token）
- `punctuation_positions`（定稿标点位置）

**输出**：
- `SentenceSegment` 列表（按标点切分，文本去除标点）
- `punctuation_marks` 元信息（可选保留原始标点位置，用于回放/调试）

**切分策略**：
1. 仅在标点位置切分，不新增或重算时间戳
2. 标点合并到邻词后已删除 token，因此切分以“词边界索引”对齐
3. 默认删除用于切分的标点字符；必要时可配置保留句末标点

### 5.5 语言切换迟滞测试（Language Switch Hysteresis）

**问题**：中英混合音频中，LangID 可能在边界处频繁切换，导致标点模型频繁加载/卸载。

**迟滞策略**：
```python
class LanguageHysteresis:
    def __init__(self, min_chunks: int = 3, confidence_threshold: float = 0.8):
        """
        min_chunks: 连续 N 个 chunk 检测到新语言才切换
        confidence_threshold: LangID 置信度阈值
        """
        self.min_chunks = min_chunks
        self.confidence_threshold = confidence_threshold
        self._current_lang = None
        self._pending_lang = None
        self._pending_count = 0

    def update(self, detected_lang: str, confidence: float) -> str:
        """返回应使用的语言（可能与检测结果不同）"""
        if confidence < self.confidence_threshold:
            # 低置信度，保持当前语言
            return self._current_lang or detected_lang

        if detected_lang == self._current_lang:
            self._pending_lang = None
            self._pending_count = 0
            return self._current_lang

        if detected_lang == self._pending_lang:
            self._pending_count += 1
            if self._pending_count >= self.min_chunks:
                # 达到阈值，切换语言
                self._current_lang = detected_lang
                self._pending_lang = None
                self._pending_count = 0
                return self._current_lang
        else:
            # 新的候选语言
            self._pending_lang = detected_lang
            self._pending_count = 1

        return self._current_lang or detected_lang
```

**测试用例**：
```python
# tests/test_language_hysteresis.py
class TestLanguageHysteresis:
    def test_no_switch_on_single_detection(self):
        """单次检测到新语言不应切换"""
        h = LanguageHysteresis(min_chunks=3)
        h.update("zh", 0.9)  # 初始化为中文
        assert h.update("en", 0.9) == "zh"  # 仍返回中文
        assert h.update("zh", 0.9) == "zh"  # 回到中文

    def test_switch_after_consecutive_detections(self):
        """连续检测到新语言应切换"""
        h = LanguageHysteresis(min_chunks=3)
        h.update("zh", 0.9)
        h.update("en", 0.9)  # 1
        h.update("en", 0.9)  # 2
        assert h.update("en", 0.9) == "en"  # 3，切换

    def test_low_confidence_keeps_current(self):
        """低置信度应保持当前语言"""
        h = LanguageHysteresis(min_chunks=3, confidence_threshold=0.8)
        h.update("zh", 0.9)
        assert h.update("en", 0.5) == "zh"  # 低置信度，保持中文
```

**配置参数**：
```yaml

  confidence_threshold: 0.8  # LangID 置信度阈值
```

## 6. 风险与缓解措施（Codex 验证后更新）

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| 标点模型本地文件缺失 | 功能不可用 | 启动时校验模型完整性，缺失时降级到 ASR 默认标点，必要时回退 DefaultSegmenter |
| 标点推理延迟过高 | 流水线瓶颈 | Int8 量化 + CPU 并发控制，按 LangID 按需加载 |
| 跨 Chunk 边界错误 | 句子断裂 | SemanticBuffer 待定区 + VAD 长停顿/说话人切换强制切分 |
| Bridge 积压 | 内存溢出 | 背压控制 + 饥饿保护 + 强制 flush |
| Whisper 幻觉 | 输出质量下降 | PunctuationArbiter 仲裁 + 低置信度回退快流 |
| 职责边界不清 | 代码混乱 | FastWorker 仅推理，标点/分句统一在流水线层 |
| 多语言模型并驻 | 内存压力 | 按语言缓存与动态卸载，限制同时加载数量 |

### 6.1 ONNX Session 管理详细配置

**ModelManager V2 已实现的机制**（复用现有架构）：

1. **LRU 缓存驱逐**：
   - `max_models`: 默认 3，限制同时加载的模型数量
   - 超出容量时自动驱逐最久未使用的模型

2. **ONNX 线程配置**（避免多模型争抢 CPU）：
```yaml
# models.yaml 中为标点模型配置
punctuation_models:
  ct_transformer_zh:
    resources:
      cpu_threads: 1  # 单线程推理，避免争抢
```

3. **懒加载策略**：
   - 仅当检测到特定语言时才加载对应模型
   - 通过 `PunctuationRegistry.get(language)` 触发按需加载

4. **空闲卸载**（建议新增）：
```python
# 在 PunctuationService 中实现
async def _idle_unload_task(self):
    """空闲 5 分钟后自动卸载非活跃模型"""
    while True:
        await asyncio.sleep(60)
        for lang, last_used in self._usage_tracker.items():
            if time.time() - last_used > 300:  # 5 分钟
                self._unload_model(lang)
```

## 7. Codex 验证结论与最终决策

### 7.1 模型选型验证结果

| 原方案 | Codex 结论 | 用户最终决策 |
|--------|------------|--------------|
| WeTextProcessing (WFST) | 更适合文本归一化，不是标点模型；过度归一化会破坏时间戳对齐 | **保留**，设计 CharMapping 时间戳映射机制解决对齐问题 |
| CT-Transformer (中文) | 与现有架构一致，适合作为核心模型；<20ms 延迟，~150MB 内存 | **保留** |
| Edge-Punct-Casing (英文) | 模型来源不明，ONNX/Int8 支持不确定 | **保留**，用户确认使用此模型 |
| PCS-47Lang (日文) | 多语标点模型，已接入本地 ONNX | **保留**，用户确认使用此模型 |

**用户决策说明**：
- WeTextProcessing 对中文 ITN（逆文本标准化）非常重要，通过 CharMapping 机制可解决时间戳对齐问题
- 英文和日文模型选择由用户明确指定，需在实施时验证 ONNX 导出可行性

### 7.2 架构兼容性检查

#### 7.2.1 与现有架构的兼容性

| 现有组件 | 兼容性 | 说明 |
|----------|--------|------|
| AsyncDualPipeline | 完全兼容 | 新增组件在流水线层调用，不修改核心流程 |
| FastWorker | 完全兼容 | 仅在 sv_result.metadata 中附加标点结果，不改变接口 |
| SlowWorker | 完全兼容 | 仅改变输入源（从 SequencedQueue 到 Bridge），接口不变 |
| ModelManager V2 | 完全兼容 | 新增 ModelSpec 类型，复用现有加载/卸载机制 |
| DefaultSegmenter | 完全兼容 | 作为降级方案保留，标点模型不可用时回退 |
| DefaultAligner | 完全兼容 | 对齐阶段不变，仅输入数据结构增强 |

#### 7.2.2 高内聚低耦合设计原则

**高内聚**：
- `PunctuationService`：封装所有标点恢复逻辑，对外仅暴露 `restore()` 接口
- `SemanticBuffer`：封装跨 Chunk 边界处理，对外仅暴露 `add()`/`flush()` 接口
- `BridgeController`：封装批次聚合逻辑，对外仅暴露 `add_semantic_chunk()`/`flush()` 接口
- `PunctuationArbiter`：封装仲裁逻辑，对外仅暴露 `arbitrate()` 接口

**低耦合**：
- 各组件通过数据类（`PunctuationResult`、`SemanticChunk`、`BridgeBatch`）通信
- 组件间无直接依赖，通过流水线层协调
- 标点模型通过 `PunctuationRegistry` 注册，支持热插拔
- 降级路径独立，任一组件失败不影响整体流程

#### 7.2.3 模型替换兼容性设计（贯穿全流程）

**设计原则已融入各阶段**：
- **Phase A.0**：定义 `PunctuationModelAdapter` 抽象基类
- **Phase B.0**：确保 `PunctuationService` 仅依赖接口
- **Phase C.0**：确保 `SemanticBuffer` 仅依赖数据结构
- **Phase G.0**：确保 `PunctuationArbiter` 与模型实现解耦

**模型替换流程**：
1. 实现新的 `PunctuationModelAdapter` 子类
2. 在 `models.yaml` 中添加新模型的 `ModelSpec`
3. 在 `PunctuationRegistry` 中注册新策略
4. 无需修改 `PunctuationService`、`SemanticBuffer`、`PunctuationArbiter` 或流水线代码

**向后兼容保证**：
- `PunctuationResult` 数据结构保持稳定
- `split_points` 格式不变，下游组件无需修改
- 模型切换通过配置完成，无需代码变更

### 7.3 替代方案

| 方案 | 描述 | 适用场景 |
|------|------|----------|
| 方案 A | 中/英/日统一采用 CT-Transformer，兜底采用 ASR 默认标点 | **推荐**，架构一致性最好 |
| 方案 B | 快流仅输出 split_points，慢流依赖 Whisper 内置标点 | 降低 CPU 负载 |

### 分支管理策略

#### 开发流程
```
main (v3.2.1)
    ↓
feature/punctuation-infrastructure (Phase A)
    ↓
feature/fast-worker-punctuation (Phase B, merge from Phase A)
    ↓
feature/semantic-buffer (Phase C, merge from Phase B)
    ↓
feature/punctuation-debug-bridge-mvp (Phase D, merge from Phase C)
    ↓ (merge to main as v3.2.2)
main (v3.2.2)
    ↓
feature/bridge-complete (Phase E)
    ↓
feature/slow-worker-batch-upgrade (Phase F, merge from Phase E)
    ↓
feature/punctuation-arbiter-splitter (Phase G, merge from Phase F)
    ↓
feature/punctuation-e2e-testing (Phase H, merge from Phase G)
    ↓ (merge to main as v3.2.3)
main (v3.2.3)
```

#### 命名规范说明

1. **功能类分支** (`feature/*`)：所有开发分支使用 `feature/` 前缀
2. **简洁描述性**：分支名简洁明了，体现核心功能
3. **连字符分隔**：使用连字符 (`-`) 分隔单词，便于阅读
4. **避免版本号**：分支名不包含版本号，通过合并时机确定版本归属

#### 合并策略

- **Phase A-D**：顺序合并，D完成后合并到 `main` 作为 v3.2.2 发布
- **Phase E-H**：顺序合并，H完成后合并到 `main` 作为 v3.2.3 发布
- **代码审查**：每个Phase合并前需通过单元测试和集成测试
- **回退机制**：每个Phase保持独立，可单独回退
