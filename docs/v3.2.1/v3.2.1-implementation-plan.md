## 1. 执行摘要

### 1.1 目标

在预处理阶段引入语言检测（LangID）和声纹提取（Speaker Embedding），为每个 AudioChunk 打上语言标签和声纹向量，成为后续标点模型、Bridge、置信度高亮的路由开关。

### 1.2 核心原则

- **左移与解耦**：所有元数据分析前置到预处理阶段，Worker 不再进行逻辑判断
- **高内聚低耦合**：作为独立模块集成到预处理流水线
- **CPU 优先**：默认 CPU 推理，多核并行，仅全量检测模式优先 GPU
- **渐进式交付**：分阶段实施，每阶段可独立测试和回滚

### 1.3 关键约束

- 与 ModelManager V2 统一管理
- 与 PreprocessCacheService 集成
- 性能影响 <5%（智能平衡模式，按第 7 章基线口径评测）
- 语言检测准确率 ≥95%（Chunk 级，按第 7 章数据集与口径验收）
- 语言编码统一采用 ISO 639-3（内部保留值 "auto" 例外）
- 声纹提取仅做预处理集成，为后续聚类预留接口

**GPU 推理配置**：

- 设备选择：`cuda:0`（默认）
- 批处理大小：64（利用 GPU 并行优势）
- 显存预算：LangID ~200MB，SpeakerEmb ~100MB

#### 设备切换机制

**配置接口**：
```python
class LanguageDetectionConfig(BaseModel):
    mode: Literal["fast", "balanced", "precise"] = "balanced"
    device: Literal["auto", "cpu", "cuda"] = "auto"  # auto = 根据模式自动选择
    enable_speaker_embedding: bool = False
```

**自动选择逻辑**：
```python
def resolve_device(config: LanguageDetectionConfig) -> str:
    if config.device != "auto":
        return config.device

    # 精准模式优先 GPU
    if config.mode == "precise" and torch.cuda.is_available():
        return "cuda"

    # 其他模式默认 CPU
    return "cpu"
```

解析后的实际设备（`resolved_device`）需要写入 langid/speaker 缓存元数据，用于命中一致性；当 `device=auto` 时以 `resolved_device` 为准进行缓存比较。

### 2.4 多核并行优化

#### CPU 并行策略

**线程分配**：
- 由 `HardwareProfileService` 提供推荐线程数
- 公式：`num_threads = max(1, cpu_count - 4)`（保留 4 核给其他任务）
- 最小值：1，最大值：`cpu_count`
- 线程配置在预处理初始化时一次性设置，避免影响 ASR/分离等并行阶段

**批处理并行**：
- 使用 PyTorch 的内置并行能力
- 通过 `torch.set_num_threads()` 控制 BLAS/OpenMP 线程
- 批处理大小根据 CPU 核心数动态调整

**实现示例**：
```python
def setup_cpu_parallelism(num_threads: int):
    torch.set_num_threads(num_threads)
    torch.set_num_interop_threads(1)  # 避免过度并行
    os.environ["OMP_NUM_THREADS"] = str(num_threads)
    os.environ["MKL_NUM_THREADS"] = str(num_threads)
```

#### 批处理优化

**Center Crop（中心裁剪）**：
- 对于 >4s 的 Chunk，仅截取中间 4s 进行推理
- 减少 70%+ 计算量，准确率损失 <2%

**Matrix Batching（矩阵批处理）**：
- 将多个 Chunk 通过 Padding 对齐，堆叠成 Batch Tensor
- 一次性推理，避免串行循环
- 批处理大小：CPU 32，GPU 64

**短音频与静音处理**：
- <3s 的 Chunk 优先与相邻 Chunk 合并到 ≥3s；无法合并则补零到 4s
- VAD 能量/语音占比低于阈值的片段标记为 "auto"，并记录低置信度

**实现示例**：
```python
def prepare_batch(chunks: List[AudioChunk], target_length: int = 4.0) -> torch.Tensor:
    """
    Center Crop + Padding + Stacking
    """
    processed = []
    for chunk in chunks:
        audio = chunk.audio_data
        sr = chunk.sample_rate

        # Center Crop
        if len(audio) > target_length * sr:
            center = len(audio) // 2
            half_len = int(target_length * sr / 2)
            audio = audio[center - half_len : center + half_len]

        # Padding
        if len(audio) < target_length * sr:
            pad_len = int(target_length * sr) - len(audio)
            audio = np.pad(audio, (0, pad_len), mode='constant')

        processed.append(torch.from_numpy(audio))

    # Stacking
    return torch.stack(processed)
```

## 3. 三种检测模式实现

### 3.1 模式 A：极速模式（Fast / Sparse Sampling）

#### 适用场景
- 绝大多数单语言视频（会议、演讲、教程）
- 用户对性能要求极高，可接受少量误判

#### 算法逻辑

**采样策略**：
- 全视频仅采样 10-15 个 Chunk（均匀分布）
- 最小采样数：8（不足则直接降级到智能平衡模式）
- 采样间隔：`total_chunks / 12`（取中间值）

**一致性判断**：
- 如果 90% 的采样结果一致（Consensus > 0.9）且平均置信度 ≥0.8，判定为单语言视频
- 将该主语言广播到所有 Chunk

**性能指标**：
- 耗时：<0.5s（10 个 Chunk，CPU 批处理）
- 准确率：单语言视频 >98%，多语言视频可能误判

#### 实现伪代码

```python
def detect_fast_mode(chunks: List[AudioChunk]) -> Dict[int, str]:
    # 1. 均匀采样
    total = len(chunks)
    step = max(1, total // 12)
    samples = [chunks[i] for i in range(0, total, step)][:15]
    if len(samples) < 8:
        # 样本不足，降级到智能平衡模式
        return detect_balanced_mode(chunks)

    # 2. 批量推理
    batch = prepare_batch(samples)
    results = langid_model.predict(batch)

    # 3. 一致性判断
    lang_counts = Counter([r.language for r in results])
    dominant_lang, count = lang_counts.most_common(1)[0]
    mean_conf = sum(r.confidence for r in results) / len(results)

    if count / len(samples) >= 0.9 and mean_conf >= 0.8:
        # 广播到所有 Chunk
        return {i: dominant_lang for i in range(total)}
    else:
        # 降级到智能平衡模式
        return detect_balanced_mode(chunks)
```

### 3.2 模式 B：智能平衡模式（Balanced / Adaptive Grouping）—— **推荐默认**

#### 适用场景
- 电影、Vlog、绝大部分未知视频
- 平衡性能和准确率

#### 算法逻辑

**宏观分组**：
- 按时间轴将 Chunk 划分为 60s 的逻辑组（Decision Window）
- 每组包含约 20-30 个 Chunk（假设 VAD 切分平均 2-3s）

**五点探测**：
- 对每组按累计时长取 `[0%, 25%, 50%, 75%, 100%]` 处的探针（去重）
- 若探针不足 3 个，直接对该组全量检测
- 批量推理探针

**组内判决**：
- 若 5 点一致 -> 该组所有 Chunk 标记为该语言
- 若不一致 -> **局部降级**：仅对该组触发全量检测

**边界缝隙微扫（Boundary Seam Micro-Scan）**：
- 若 `Group[i]` 为 zho，`Group[i+1]` 为 eng 且置信度偏低或分布多峰
- 触发微扫：对 `Group[i]` 的后 25% 和 `Group[i+1]` 的前 25% 进行全量检测
- 精修语言切换的精确边界

#### 性能指标
- 耗时：1-2s（60min 视频，约 1800 个 Chunk）
- 准确率：>95%（Chunk 级）
- 覆盖率：平均检测 30-40% Chunk

#### 实现伪代码

```python
def detect_balanced_mode(chunks: List[AudioChunk]) -> Dict[int, str]:
    results = {}

    # 1. 宏观分组（60s）
    groups = group_by_time(chunks, window_seconds=60)

    # 2. 收集所有探针
    probes = []
    probe_map = {}  # {probe_idx: (group_idx, chunk_index)}

    for g_idx, group in enumerate(groups):
        positions = [0.0, 0.25, 0.50, 0.75, 1.0]
        probe_chunks = select_probes_by_time(group, positions)  # 按累计时长取样并去重

        if len(probe_chunks) < 3:
            full_batch = prepare_batch(group)
            full_results = langid_model.predict(full_batch)
            for chunk, res in zip(group, full_results):
                results[chunk.index] = res.language
            continue

        for chunk in probe_chunks:
            probe_map[len(probes)] = (g_idx, chunk.index)
            probes.append(chunk)

    # 3. 批量推理探针
    if probes:
        probe_batch = prepare_batch(probes)
        probe_results = langid_model.predict(probe_batch)
    else:
        probe_results = []

    # 4. 组内判决
    for g_idx, group in enumerate(groups):
        # 提取该组的探针结果
        group_probe_indices = [p_idx for p_idx, (g, _) in probe_map.items() if g == g_idx]
        group_probes = [probe_results[p_idx] for p_idx in group_probe_indices]
        if not group_probes:
            continue

        # 一致性判断
        lang_counts = Counter([r.language for r in group_probes])
        dominant_lang, count = lang_counts.most_common(1)[0]

        if count == len(group_probes):
            # 一致，广播
            for chunk in group:
                results[chunk.index] = dominant_lang
        else:
            # 不一致，局部全量检测
            full_batch = prepare_batch(group)
            full_results = langid_model.predict(full_batch)
            for chunk, res in zip(group, full_results):
                results[chunk.index] = res.language

    # 5. 边界微扫
    refine_boundaries(groups, results, chunks)

    return results
```

### 3.3 模式 C：精准模式（Precise / Full Scan）

#### 适用场景
- 复杂的多语言访谈、强干扰环境
- 用户强制指定，或智能平衡模式检测到高度不一致

#### 算法逻辑

**全量检测**：
- 对所有 Chunk 进行批量推理
- 依然应用 Center Crop 优化

**GPU 加速**：
- 默认优先使用 GPU（如果可用）
- 批处理大小：64

#### 性能指标
- 耗时：2-4s（60min 视频，1800 个 Chunk，GPU）
- 准确率：>98%（Chunk 级）

#### 实现伪代码

```python
def detect_precise_mode(chunks: List[AudioChunk]) -> Dict[int, str]:
    results = {}

    # 1. 全量批处理
    batch_size = 64
    for i in range(0, len(chunks), batch_size):
        batch_chunks = chunks[i:i+batch_size]
        batch = prepare_batch(batch_chunks)
        batch_results = langid_model.predict(batch)

        for chunk, res in zip(batch_chunks, batch_results):
            results[chunk.index] = res.language

    return results
```

## 5. 预处理流水线集成方案

### 5.1 插入点选择

#### 最终决策：VAD 后 → 频谱分诊 → 分离 → LangID → 声纹提取

**插入位置**：
1. **语言检测（LangID）**：分离后执行
   - 理由：分离后语音更干净，降低噪声/音乐干扰，提高检测稳定性
   - 时机：在 `PreprocessingPipeline.run()` 中，分离完成后、转录入队前
   - 回退：若未启用分离，则在频谱分诊后立即执行（使用 VAD 原始片段）

2. **声纹提取（Speaker Embedding）**：LangID 后执行（可选）
   - 理由：与 LangID 共享分离后音频，保持事件顺序一致
   - 回退：LangID 关闭或失败不影响声纹提取（独立开关）

**流程图**：
```
音频提取 → VAD 切分 → 频谱分诊 → 人声分离 → [LangID] → [声纹提取] → 转录队列
                                     ↓               ↓
                               language 标签   speaker_embedding
```

---

### 5.1.1 LangID 与声纹提取是否需要同轮执行

**结论**：建议同一预处理轮次串行执行（LangID → 声纹提取），不要求并行或融合。

**原因**：
- 模型与输入策略不同：LangID 偏短窗与中心裁剪，声纹偏更长语音片段，强行合并会牺牲精度
- 独立缓存与失败隔离更稳妥：LangID 失败不影响声纹提取，反之亦然
- 可共享重采样/切片/批处理构建，减少重复 IO，但推理阶段保持解耦
- 若仅启用声纹提取，可跳过 LangID；若仅启用 LangID，不触发声纹

### 5.2 缓存策略

#### 缓存阶段扩展

在 `PreprocessCacheService` 中新增两个缓存阶段：

**langid 阶段**：
```python
cache_preprocess/
├── manifest.json
├── vad/
├── triage/
├── separation/
├── langid/                    # 新增
│   ├── language_map.json      # {chunk_index: {language, confidence, scores}}
│   ├── progress.json          # {complete, processed_indices, last_batch_end, total_chunks}
│   └── metadata.json          # {schema_version, mode, model_id, model_revision, model_sha256, center_crop_duration, min_duration, batch_size, resolved_device, torch_version, speechbrain_version, language_code_standard}
└── speaker/                   # 新增
    ├── embeddings.npy         # float32 数组 (N, 192)
    ├── index_map.json         # {chunk_index: embedding_index}
    ├── progress.json          # {complete, processed_indices, last_batch_end, total_chunks}
    └── metadata.json          # {schema_version, model_id, model_revision, model_sha256, embedding_dim, resolved_device, torch_version, speechbrain_version}
```

写入采用临时文件 + 原子替换策略，避免中途中断导致缓存损坏。

#### 缓存命中条件

**LangID 缓存有效条件**：
- `schema_version` 一致
- `mode` 一致（fast/balanced/precise）
- `model_id` 一致
- `model_revision`/`model_sha256` 一致
- `center_crop_duration` 一致（默认 4.0s）
- `min_duration` 一致（默认 3.0s）
- `batch_size` 一致
- `resolved_device` 一致（cpu/cuda）
- `torch_version`/`speechbrain_version` 一致
- `language_code_standard` 一致

**声纹缓存有效条件**：
- `schema_version` 一致
- `model_id` 一致
- `model_revision`/`model_sha256` 一致
- `embedding_dim` 一致（192）
- `resolved_device` 一致
- `torch_version`/`speechbrain_version` 一致

`langid_confidence_threshold` 不影响缓存命中，阈值在加载后派生最终语言标签。

#### 增量缓存与暂停恢复策略

**目标**：暂停后尽量少重算，恢复时仅补算缺失 Chunk。

**策略要点**：
- 每个 batch 处理完写入 `language_map.json`/`embeddings.npy`，并更新 `progress.json`
- `progress.json` 使用 `complete=false` 表示阶段未完成，可用于恢复
- 收到暂停信号时强制刷盘并写入最新 `progress.json`
- 恢复时校验元数据；若 `complete=false`，仅补算缺失索引并合并结果

**进度示例**：
```json
{
  "complete": false,
  "processed_indices": [0, 1, 2, 3],
  "last_batch_end": 3,
  "total_chunks": 1800
}
```

#### 缓存失效处理

```python
def recover_langid_cache(job_id: str, chunks: List[AudioChunk]) -> Optional[Tuple[Dict[int, Dict[str, Any]], List[int]]]:
    """
    恢复语言检测缓存
    """
    cache_dir = get_cache_dir(job_id) / "langid"

    # 1. 校验元数据
    metadata = load_json(cache_dir / "metadata.json")
    if not validate_langid_metadata(metadata, current_config):
        logger.warning("LangID 缓存元数据失配，自动失效")
        return None

    # 2. 加载语言映射
    language_map = normalize_langid_map(load_json(cache_dir / "language_map.json"))  # 统一为 int 索引
    progress = load_json(cache_dir / "progress.json", default={"complete": True})

    # 3. 校验完整性
    if progress.get("complete", True) and set(language_map.keys()) != set(c.index for c in chunks):
        logger.warning("LangID 缓存不完整，自动失效")
        return None

    missing = [c.index for c in chunks if c.index not in language_map]
    return language_map, missing
```

#### AudioChunk 扩展（已在第 4 章定义）

```python
class AudioChunk(BaseModel):
```

#### PreprocessingPipeline 改造

```python
class PreprocessingPipeline:
    async def run(self, job_id: str, config: PreprocessingConfig) -> List[AudioChunk]:
        # 1. VAD 切分
        chunks = await self.vad_stage.run(...)

        # 2. 频谱分诊
        await self.triage_stage.run(chunks, ...)

        # 3. 人声分离（未启用分离则跳过）
        await self.separation_stage.run(chunks, ...)

        # 4. 尝试恢复 LangID 缓存（支持增量恢复）
        recovered = self.cache_service.recover_langid_cache(job_id, chunks)
        if recovered is None:
            lang_map = {}
            missing = [c.index for c in chunks]
        else:
            lang_map, missing = recovered

        if missing:
            # 5. 执行语言检测（仅补算缺失）
            target_chunks = [c for c in chunks if c.index in set(missing)]
            new_map, metadata = await self.langid_stage.run(
                chunks=target_chunks,
                mode=config.language_detection_mode,
                device=config.language_detection_device
            )
            lang_map.update(new_map)

            # 6. 写入缓存（增量刷新 + 进度）
            self.cache_service.save_langid_cache(job_id, lang_map, metadata, progress=build_progress(...))

        # 7. 将语言标签写入 AudioChunk
        for chunk in chunks:
            info = lang_map.get(chunk.index)
            if not info:
                chunk.language = "auto"
                chunk.language_confidence = 0.0
                continue
            chunk.language = info["language"]
            chunk.language_confidence = info["confidence"]
            if chunk.language_confidence < config.langid_confidence_threshold:
                chunk.language = "auto"

        # 8. 声纹提取（可选，支持增量恢复）
        if config.enable_speaker_embedding:
            recovered = self.cache_service.recover_speaker_cache(job_id, chunks)
            if recovered is None:
                emb_map = {}
                missing = [c.index for c in chunks]
            else:
                emb_map, missing = recovered

            if missing:
                target_chunks = [c for c in chunks if c.index in set(missing)]
                new_map = await self.speaker_stage.run(target_chunks, ...)
                emb_map.update(new_map)
                self.cache_service.save_speaker_cache(job_id, emb_map, metadata, progress=build_progress(...))

            for chunk in chunks:
                chunk.speaker_embedding = emb_map.get(chunk.index)

        return chunks
```

## 7. 评测基线与验收标准

### 7.1 数据集与标注

- 总时长 ≥20h，Chunk 数 ≥5k
- 单语言视频 ≥60%，多语言视频 ≥30%，强噪声/混响 ≥10%
- 核心语言覆盖：zho/eng/jpn/kor/yue，每种 ≥2h，另含 ≥5 种长尾语言
- 标注粒度为 Chunk 级 top-1 语言；不可判定/静音标注为 `und`（ISO 639-3）

### 7.2 指标口径

- Chunk 级准确率 = 正确语言标签 / 总 Chunk（`auto` 视为 `und` 参与统计）
- 报告 micro-accuracy + macro-F1（至少覆盖核心语言）
- 低置信度比例与 `auto` 覆盖率需单独报告

### 7.3 性能基线

- 基线对比：v3.2.0 预处理流水线（同输入、同硬件、同配置）
- 统计 P50/P95 总预处理时长、LangID 阶段耗时、CPU 利用率与峰值内存
- “性能影响 <5%”以智能平衡模式下 P95 预处理时长增幅 ≤5% 为准

### 7.4 复现与记录

- 固定模型 revision/sha256 与依赖版本（torch/speechbrain），记录到评测报告
- 记录评测数据集版本、随机种子、配置快照与硬件配置

## 9. PBT 属性和不变量

### 9.1 语言检测不变量

**INV-1: 语言标签完整性**
```python
@property
def language_labels_complete(chunks: List[AudioChunk]) -> bool:
    """所有 Chunk 必须有语言标签（即使是 'auto'）"""
    return all(chunk.language is not None for chunk in chunks)
```

**INV-2: 置信度范围**
```python
@property
def confidence_in_range(chunks: List[AudioChunk]) -> bool:
    """置信度必须在 [0, 1] 范围内"""
    return all(
        chunk.language_confidence is None or
        0.0 <= chunk.language_confidence <= 1.0
        for chunk in chunks
    )
```

**INV-3: 缓存一致性**
```python
@property
def cache_consistency(cached_map: Dict, current_chunks: List[AudioChunk], progress: Dict) -> bool:
    """complete=true 时必须完整一致；增量缓存时只要求子集一致"""
    chunk_indices = set(c.index for c in current_chunks)
    cached_indices = set(cached_map.keys())
    if progress.get("complete", True):
        return cached_indices == chunk_indices
    return cached_indices.issubset(chunk_indices)
```

### 9.2 声纹提取不变量

**INV-4: Embedding 维度一致性**
```python
@property
def embedding_dim_consistent(chunks: List[AudioChunk]) -> bool:
    """所有 Embedding 必须是 192 维"""
    embeddings = [c.speaker_embedding for c in chunks if c.speaker_embedding is not None]
    return all(len(emb) == 192 for emb in embeddings)
```

**INV-5: Embedding 数值有效性**
```python
@property
def embedding_values_valid(chunks: List[AudioChunk]) -> bool:
    """Embedding 值必须是有限浮点数"""
    embeddings = [c.speaker_embedding for c in chunks if c.speaker_embedding is not None]
    return all(
        all(math.isfinite(v) for v in emb)
        for emb in embeddings
    )
```

### 9.3 模式切换不变量

**INV-6: 模式升级单向性**
```python
@property
def mode_upgrade_monotonic(mode_history: List[str]) -> bool:
    """模式只能从 fast → balanced → precise，回退需显式重启流程"""
    mode_order = {"fast": 0, "balanced": 1, "precise": 2}
    return all(
        mode_order[mode_history[i]] <= mode_order[mode_history[i+1]]
        for i in range(len(mode_history) - 1)
    )
```

## 10. 技术风险与缓解

### 10.1 性能风险

**风险 1：CPU 推理速度不足导致预处理时间显著上升**
- **影响**：60 分钟视频的预处理时间从 30s 增加到 60s+
- **缓解**：
  - 默认使用智能平衡模式，仅检测 30-40% Chunk
  - 提供极速模式作为快速预览选项
  - 优化 Center Crop 和 Matrix Batching
  - 与硬件能力提供者集成，动态调整批处理大小

**风险 2：GPU 与 ASR 竞争显存导致 OOM 或频繁驱逐**
- **影响**：精准模式下 GPU 推理失败，回退到 CPU
- **缓解**：
  - 默认 CPU 推理，仅精准模式优先 GPU
  - 在显存策略中将 LangID/Speaker 标记为低优先级
  - 提供显存预算检查，不足时自动回退 CPU

### 10.2 准确率风险

**风险 3：短音频/强口音导致 LangID 精度不稳定**
- **影响**：<2s 的 Chunk 或方言音频误判率高
- **缓解**：
  - 设置置信度阈值（默认 0.7），低于阈值标记为 "auto"
  - 智能平衡模式的边界微扫机制
  - 提供手动修正接口（v3.2.4）

**风险 4：多语言同块导致标签抖动**
- **影响**：语言切换边界的 Chunk 标签不稳定
- **缓解**：
  - 边界微扫机制精修切换点
  - 降级为 "auto"，交给 ASR 自动检测
  - 记录冲突日志供后续分析

### 10.3 兼容性风险

**风险 5：SpeechBrain/torch 依赖版本冲突或环境不一致**
- **影响**：模型加载失败，整个功能不可用
- **缓解**：
  - 在 ModelManager V2 中统一依赖管理
  - 提供依赖检查脚本
  - 模型加载失败时自动降级到 "auto"

### 10.4 数据安全与隐私风险

**风险 6：声纹 embedding 属于生物特征数据，存储/传输存在合规风险**
- **影响**：潜在合规问题、数据泄露风险提升
- **缓解**：
  - 默认关闭声纹提取
  - 缓存与持久化加密、访问控制最小化
  - SSE/日志不下发 embedding，仅传递统计
  - 设置保留期与清理策略

### 10.5 替代方案

**方案 1：使用 Whisper 内置语言检测作为快速兜底**
- **优势**：无需额外模型，集成简单
- **劣势**：需要转录才能检测，无法前置
- **适用场景**：LangID 模型不可用时的紧急回退

**方案 2：声纹改用 pyannote.audio 或 Resemblyzer**
- **优势**：依赖更轻/精度不同
- **劣势**：需要重新集成和测试
- **适用场景**：SpeechBrain 声纹模型不满足需求时

**方案 3：只在检测到多语言风险时启用 LangID**
- **优势**：大幅减少性能开销
- **劣势**：需要额外的多语言风险检测逻辑
- **适用场景**：性能要求极高的场景
