# P0：L0–L7 收口与说话人硬边界修复方案（不引入 LLM）

> Type: Plan | Status: Draft  
> Version: V3.2.0+dev.20260207.03  
> Scope: Dual-Balanced（双流定稿主路径）  
> Non-Goal: 不引入 LLM、不接入 Pyannote segmentation、不修 CI（仅补单测）

## 1. 目标（必须达成）

1) **打通 L5/L6 的 speaker 信号链（P0）**  
* `speaker_change` 必须真实影响：  
  - Bridge flush（避免多人语音混入一个 Whisper batch）  
  - L6 强断句（不同 speaker 绝不合并为同一字幕句段）  

2) **不依赖标点也能稳定切分**  
* 关闭 L3 标点或标点覆盖率低时，L6 仍能靠“停顿/VAD + 长度硬约束 + speaker 硬边界”稳定断句。  

3) **定稿路径收口**  
* 定稿只走：`L4 -> L5 -> L6 -> L7`  
* `default_segmenter` / 历史同职分句器仅允许用于草稿路径（或明确下线）。  

4) **bridge/speaker_policy 纳入运行参数系统**  
* 支持热更新与可回滚（便于对比与回归）。  

## 2. 现状核对（基于当前代码事实）

### 2.1 预处理阶段已具备 speaker 信号

* `backend/app/pipelines/preprocessing_pipeline.py` Stage6 已将 `chunk.primary_speaker_id` 写入 chunk（在线聚类输出）。

### 2.2 speaker 信号已进入语义缓冲输入，但下游未形成闭环

* `backend/app/pipelines/async_dual_pipeline.py` 的 `_build_semantic_input()` 已调用 `_extract_primary_speaker_id(chunk)` 并把 `speaker_id` 填进 `SemanticBufferInput`。  
* `backend/app/services/punctuation/semantic_buffer.py` 内已支持 speaker_change 触发 `flush()`（前提是 `item.speaker_id` 有值且发生变化）。  
* `backend/app/services/bridge/bridge_controller.py` 内已支持 speaker_change 触发 `_build_batch(flush_reason="speaker_change")`。

### 2.3 L5/L6 当前对 speaker 基本“失明”

* `backend/app/services/punctuation/semantic_injection_processor.py`：构建 `AnnotatedWord` 时把 `speaker_id=None` 写死。  
* `backend/app/services/segmentation/segmentation_processor.py`：仅调用 `FinalSplitter.split()`，未按 speaker 做硬边界切分/合并约束。  

### 2.4 Bridge speaker_change flush 存在“状态更新不完整”的潜在问题

* `BridgeController.add_semantic_chunk()` 在 `speaker_change`、`long_pause` 这类 pre_flush 分支中：会先构建 batch（pop 老队列），再 push 新 chunk，但**未同步更新 `_last_speaker_id/_last_audio_end/_last_input_time`**。  
* 风险：在某些边界连续到来时，可能导致“过度 flush（批次过碎）”或 speaker 状态滞后，削弱“同 speaker 合并短句”的收益。  

> 说明：本 P0 必须把 “speaker_change 只在边界处触发一次强 flush” 做到可预期，避免 batch 退化成每 chunk 一个。

### 2.5 定稿路径仍存在同职分支残留

* 代码里仍存在 `default_segmenter.py` 等历史入口（部分已标注“仅草稿/过渡”但尚未彻底收口）。  
* 本 P0 要求：定稿绝不再走多条同职路径，减少维护成本和回归风险。

## 3. 设计决策（P0 约束）

### 3.1 speaker 信号的最小粒度（P0 先用 chunk 级）

* P0 不引入 Pyannote segmentation，因此 speaker 粒度先以“chunk 级主说话人”为主：`chunk.primary_speaker_id`。  
* 对 L6 来说：即便粒度不完美，也能显著降低“跨 speaker 合并导致超长字幕”的概率。  

### 3.2 speaker 硬边界定义

* 当相邻词（或相邻 AnnotatedWord）`speaker_id` 不同：  
  - **必须切分**（hard-boundary）  
  - **禁止合并**（merge 禁止跨 speaker）  

### 3.3 标点依赖策略（符合你的要求）

* 默认：标点是**弱信号**，不是切分的硬依赖。  
* P0 验收：在 `punct_track.positions=[]` 时，L6 仍能稳定产出合理句段（靠停顿+长度+speaker）。  

## 4. 改动清单（按层级/文件/符号）

> 说明：以下是“需要做什么”的完整清单；本轮你要求先出文档，不直接动代码。

### 4.1 类型契约调整（L5/L6 接口）

**文件**：`backend/app/services/alignment/types.py`

* 扩展 `L5Input`：新增 `speaker_id: Optional[str] = None`（P0 先用 chunk 级 speaker）。
* 约束：`L5Output.annotated_words[*].speaker_id` 必须填充为：
  - 优先：`L5Input.speaker_id`
  - 若为空：保持 None（并在 L6 走“无 speaker 信号”的退化路径）

### 4.2 L5：SemanticInjectionProcessor 写入 speaker_id

**文件**：`backend/app/services/punctuation/semantic_injection_processor.py`

* 当前问题：`AnnotatedWord.speaker_id=None` 写死。
* 改造：  
  - 从 `data.speaker_id` 读取 speaker，并写入每个 `AnnotatedWord.speaker_id`。  
  - 仅做“字段透传”，不在 L5 做 speaker 分段（保持单职责）。  
* 单测建议：  
  - 输入有 `speaker_id` 时，输出所有 `AnnotatedWord.speaker_id` 相同且非空。  
  - 输入无 `speaker_id` 时，保持 None。

### 4.3 L6：SegmentationProcessor 按 speaker run 强断句

**文件**：`backend/app/services/segmentation/segmentation_processor.py`

* 新增步骤：在 `words_for_split` 构建前，对 `annotated_words` 做分组：  
  - 连续相同 `speaker_id` 视为一个 run  
  - `speaker_id` 变化处强制断开  
* 对每个 run：调用现有 `FinalSplitter.split()` 生成 `SentenceSegment[]`，再拼接为最终结果。  
* 合并规则：禁止跨 speaker 合并短句（即便很短，也不跨 run 合并）。  
* 退化路径：若 speaker_id 全为空或不足以形成边界，则回退到现有逻辑（只靠停顿/长度）。  
* `segmentation_report` 新增统计字段（便于验收与回归）：  
  - `speaker_run_count`  
  - `speaker_forced_split_count`（由 speaker 边界触发的切分次数）  

### 4.4 Bridge：speaker_change flush 状态更新补齐

**文件**：`backend/app/services/bridge/bridge_controller.py`

* 目标：speaker_change pre_flush 分支推入新 chunk 后，应同步更新：  
  - `_last_input_time`  
  - `_last_audio_end`  
  - `_last_speaker_id`（至少更新为新 speaker）  
  - `_last_language`（保持一致）  
* 防止行为退化：避免边界处 flush 后，下一句同 speaker 仍被误判为 speaker_change 反复 flush。
* 单测建议：  
  - 连续三段：A（speaker=1）→ B（speaker=2）→ C（speaker=2）  
    - 期望：只在 A→B 处触发一次 speaker_change flush；B 与 C 允许进入同一批次（受其他阈值控制）。

### 4.5 Pipeline：把 speaker_id 送入 L5Input（闭环关键）

**文件**：`backend/app/pipelines/async_dual_pipeline.py`

* 在 `_run_l4_to_l6_once()` 调用 L5Processor 时，补充：  
  - `L5Input(..., speaker_id=<当前chunk主说话人>)`
* speaker_id 来源：  
  - 优先：`ctx.audio_chunk.primary_speaker_id`（预处理在线聚类产物）  
  - 兜底：`None`

> 注意：这是“L5/L6 speaker 链路打通”的关键连接点。仅改 Processor 内部而不改 pipeline，speaker 仍无法进入 L6。

### 4.6 定稿路径收口：default_segmenter 仅草稿或下线

**文件**：`backend/app/services/segmentation/default_segmenter.py`、`backend/app/services/segmentation/__init__.py`、`backend/app/pipelines/async_dual_pipeline.py`

* 目标：定稿只走 `L4->L5->L6->L7`：  
  - 对齐定稿阶段不再调用 `DefaultSegmenter`/历史 `UnifiedSplitter` 分支。  
  - `DefaultSegmenter` 若保留，仅用于 fast-only 草稿模式（并在文档与代码注释中明确）。  
* 兼容策略：保留必要的“安全兜底”（例如空输入时单句输出），但不要保留“同职并行路径”。

### 4.7 运行参数系统：bridge/speaker_policy 组落地

**文件**：`backend/app/services/model_runtime_config_service.py`、`backend/app/services/text_pipeline_config.py`、`backend/app/api/routes/model_runtime_routes.py`

* 新增 `bridge.*`：  
  - 与 `BridgeConfig` 对齐（min/max batch、starvation、overlap、long_pause、dynamic_batch 等）  
  - 支持热更新（用于回滚与调参）
* 新增 `speaker_policy.*`（P0 最少项）：  
  - `enable`（是否启用 speaker 硬边界）  
  - `change_threshold`/`hysteresis_chunks`（若未来要把聚类阈值外露）  
  - `allow_multi_track`（预留，不在 P0 落地）  
* P0 生效点：  
  - `speaker_policy.enable` 控制 L6 是否启用 speaker run 切分  
  - `bridge.*` 控制 BridgeController 运行阈值（替代 dataclass 固定默认值）

## 5. 单测计划（仅单测，不动 CI）

> 建议优先在 `backend/tests` 体系补齐（当前 repo 已有大量相关单测）。

1) **L5 注入 speaker_id 单测**  
* 覆盖：有 speaker_id / 无 speaker_id

2) **L6 speaker hard-boundary 单测**  
* 输入：AnnotatedWord 序列（speaker=1 若干词，speaker=2 若干词）  
* 期望：输出句段边界至少在 speaker 变化处切开；且不跨 speaker 合并。

3) **Bridge speaker_change 状态更新回归测试**  
* 覆盖：A(1)→B(2)→C(2) 不出现“反复 speaker_change flush”的退化行为。

4) **无标点稳定切分回归**  
* `punct_track.positions=[]`，仍能按停顿/长度产出合理句段（不出现超长句率飙升）。

## 6. 验收标准（P0 Definition of Done）

* **功能闭环**：
  - 预处理聚类产生的 `primary_speaker_id` 能影响 Bridge flush 与 L6 切分。  
* **稳定性**：
  - 关闭标点或标点覆盖率极低时，仍不会出现大量超长字幕（>10s 或 >50 token）。  
* **收口**：
  - 定稿路径唯一为 `L4->L5->L6->L7`，不存在 DefaultSegmenter 等同职并行定稿分支。  
* **可回滚**：
  - `speaker_policy.enable=false` 时系统行为回退到现有“无 speaker 硬边界”版本。  
* **单测通过**：
  - 新增/修改单测全部通过，且不引入长时间测试（单测单次运行建议 <60s）。

## 7. 风险与缓解

* **speaker_id 粒度粗（chunk级）导致“同一句被切开”**：  
  - P0 可接受：优先解决“跨 speaker 合并导致超长字幕”。  
  - 后续 P1 才考虑 Pyannote turn 级精修与更细粒度贴标。  
* **Bridge 批次过碎影响 Whisper 吞吐**：  
  - 通过修复 pre_flush 状态更新 + 合理 batch 阈值（bridge.*）缓解。  
* **语义注入覆盖率低**：  
  - L5 门控已存在；P0 重点是 speaker 硬边界，不依赖注入成功。  

## 8. 本轮明确不做（避免工程扩散）

* 不接入 Pyannote segmentation / global clustering（P1）。  
* 不引入 LLM（P3）。  
* 不修 CI（但会确保单测可本地稳定运行；CI 缺失项后续单独处理）。
