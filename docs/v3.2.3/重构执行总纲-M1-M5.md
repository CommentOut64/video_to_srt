# v3.2.3 重构执行总纲（M1-M5）

> Type: Architecture | Status: Active
> Version: V3.2.0+dev.20260213.02
> Scope: 仅覆盖 M1-M5 计划，不包含 M0 基线冻结细节

## 1. Summary

* **Goal**: 以“Pyannote 软切 + 后处理简化 + NW V2 + LLM 语义切分 + 双 Epoch 性能优化”为主线，完成 v3.2.3 的后处理与切分体系重构。
* **核心策略**:
  - M1 先把软切能力和后续简化接口一起落地，避免二次返工。
  - M2 合并后处理简化与 Needleman-Wunsch V2，形成稳定主链路。
  - M3 逐步引入 LLM 语义切分，标点从主路径降级为备用路径。
  - M4 做 S-Epoch/W-Epoch 性能收敛，不让 LLM 阻塞主流程。
  - M5 做清理收尾，确保“实现真相=文档真相”。

## 2. Diagram

* `M1 Pyannote软切+接口预埋` -> `M2 后处理简化+NW V2` -> `M3 LLM语义切分渐进替换标点` -> `M4 S/W Epoch性能优化` -> `M5 清理收尾`
* `speaker_change(事件)` -> `待切窗口` -> `锚点裁决(停顿/语义/标点)` -> `deferred生命周期` -> `输出追踪`
* `快流草稿` + `慢流结果` + `说话人证据` -> `四模块决策链` -> `最终句段`

## 4. 阶段切分与依赖关系

1. M1 是 M2 的前置。
2. M2 完成后，M3 才进入“仲裁/主用”阶段。
3. M3 进入灰度后，M4 才做以真实流量为基础的性能调参。
4. M4 结束后，M5 才能删除历史补丁与参数。

## 5. 全量讨论结论归档映射（防遗漏）

1. **漏切并非无解**  
说明：即便 Pyannote 出现漏检，也可通过多证据融合、延迟纠错、慢流/LLM 复核降低漏切。  
落地：`M1` 第 7 章。

2. **切分优先级（P0-P3）**  
说明：P0 约束 > P1 说话人变化事件 > P2 锚点选择 > P3 延迟兜底。  
落地：`M1` 第 4 章。

3. **speaker_change 高/中/低分级公式**  
说明：基于 Pyannote 置信度 + 声纹距离 + 停顿等加权评分。  
落地：`M1` 第 5 章。

4. **去抖与冷却机制**  
说明：动态冷却窗口、A->B->A 回弹识别、快速对话豁免。  
落地：`M1` 第 6 章。

5. **deferred_cut 生命周期**  
说明：创建 -> 等待停顿/锚点 -> resolved/forced/slow_or_llm_revisit。  
落地：`M1` 第 8 章。

6. **P0 冲突优先级修正**  
说明：`禁句中硬切 > 禁跨高置信speaker_change合并 > 尽量避免1词孤句`。  
落地：`M1` 第 4.3 节。

7. **语义锚点定义与标点代理**  
说明：先用标点+规则做代理，LLM 作为后续语义提供者。  
落地：`M3` 第 4 章。

8. **后处理四模块数据契约**  
说明：`FactBuilder -> EvidenceFusion -> SoftCutDecisionEngine -> OutputTrace`。  
落地：`M1` 第 9 章（预埋） + `M2` 第 4 章（正式切换）。

9. **快慢流仅重算受影响窗口**  
说明：定义 affected window 触发条件与重算策略。  
落地：`M2` 第 5 章。

10. **窗口堆积风险与上限策略**  
说明：`MAX_DEFERRED_WINDOWS=3`，超限强制处理最老窗口。  
落地：`M1` 第 8.4 节 + `M4` 第 6.4 节。

11. **LLM 延迟风险与异步修订机制**  
说明：LLM 不阻塞主链，修订通过 SSE 增量推送。  
落地：`M3` 第 6 章 + `M4` 第 6.5 节。

12. **Needleman-Wunsch 改造方向**  
说明：将置信度与先验引入 DP 打分，且给 LLM 先验留接口。  
落地：`M2` 第 6 章。

13. **Pyannote 帧步长到快流时间轴映射缺口**  
说明：现状代码有 `frame_start + idx*frame_step`，但文档未定义映射契约。  
落地：`M2` 第 7 章（补齐契约）。

14. **标点替换路线**  
说明：`shadow -> 仲裁 -> LLM主用+标点备用 -> 评估后决定是否移除标点主链`。  
落地：`M3` 第 5 章。

15. **S-Epoch/W-Epoch 性能优化主线**  
说明：GPU 串行占用、superblock、异步复核、增量重算。  
落地：`M4` 全文。

## 6. 阶段目标与里程碑（不含 M0）

1. **M1（1-2 周）**  
目标：软切能力落地 + 后处理简化接口预埋。  
退出门槛：无句中硬切回归，漏切下降，接口可被 M2 直接接管。

2. **M2（2 周）**  
目标：后处理简化 + NW V2 一次收口。  
退出门槛：四模块主链稳定；加权 NW 生效；时延不明显回退。

3. **M3（2-4 周）**  
目标：LLM 语义切分渐进接管。  
退出门槛：LLM 主路径稳定，标点降级为备用且不影响可用性。

4. **M4（2 周）**  
目标：双 Epoch 吞吐与延迟优化。  
退出门槛：首条可见延迟下降或持平，吞吐提升，GPU 峰值可控。

5. **M5（1 周）**  
目标：清理旧逻辑、参数收敛、文档定稿。  
退出门槛：回归通过，三模式稳定，文档与代码一致。

## 7. 全局验收原则

1. 不再允许“说话人边界直接硬切句”回到主链路。
2. 所有切分结果必须可追溯到证据轨与裁决日志。
3. LLM 只能做增强，不得阻塞主流程可用性。
4. 所有阶段均需可灰度、可回退、可量化。
