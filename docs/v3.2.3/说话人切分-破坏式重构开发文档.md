# 说话人切分系统破坏式重构开发文档（v3.2.3）

> Type: Architecture | Status: Draft  
> Version: V3.2.0+dev.20260210.05  
> Scope: 仅覆盖说话人切分/双流协同/Bridge 与后处理，不包含 LLM 切分  
> Non-Goal: 本方案明确不做兼容性适配层，不保留旧字段兜底分支

---

## 1. 目标与原则

### 1.1 总目标

在不考虑兼容性的前提下，对当前双流架构执行一次彻底重构，建立“以说话人时间线为中心”的新主链路，解决以下三个核心问题：

1. Pyannote segmentation 与 Whisper 的显存冲突与时序阻塞；
2. 在线增量聚类误分裂（3 人被识别成 10 人）；
3. Bridge 语义边界不清导致 Whisper 幻觉。

### 1.2 设计原则（强约束）

1. **简洁优先**：不为历史兼容保留分支，不引入适配器链；
2. **边界清晰**：按领域拆分职责，禁止跨层读写内部状态；
3. **高内聚低耦合**：每个模块只消费标准契约对象；
4. **深度复用+深度改造**：复用现有三循环主干与处理器能力，但允许重写核心数据流；
5. **分阶段可测试/可回退**：每个阶段独立验收，回退依赖 Git Tag 而非运行时兼容逻辑。

## 2. 最终架构（目标态）

### 2.1 核心思想

新架构以 `SpeakerTimeline` 为唯一结构真相源（Single Source of Truth）：

- 快流负责时间锚点与草稿可见性；
- S-Epoch 负责说话人时间线构建；
- W-Epoch 负责按单说话人组批进行慢流识别；
- L4-L7 负责对齐、注入、切分与输出。

### 2.2 总体流程

```text
Preprocessing(无speaker字段写回Chunk)
  └─ VAD + 分诊 + 分离 + LangID

Fast Loop(常开)
  └─ SenseVoice -> DraftCache -> Draft SSE

S-Epoch(按块运行, 独占GPU)
  └─ 声纹提取 + 聚类 + segmentation -> SpeakerTimeline

Bridge(仅消费SpeakerTimeline)
  └─ TurnGroup(单speaker目标音频 + 文本上下文)

W-Epoch(按块运行, 独占GPU)
  └─ Whisper(仅处理TurnGroup目标音频)

Finalize(L2->L7)
  └─ 仲裁 -> 对齐 -> 注入 -> 切分 -> ReplaceChunk/Turn
```

### 2.3 GPU 调度策略（解决阻塞与爆显存）

- 切分为 `SuperBlock`（建议 6~10 分钟）执行；
- 每个块严格执行：`S-Epoch -> W-Epoch`；
- S-Epoch 与 W-Epoch 不并载，不共享显存驻留；
- Fast Loop 可并行运行（CPU/ONNX 小模型），其结果先缓存；
- 首块采用“小块先行”（60~90 秒）缩短首条可定稿延迟。

## 3. 领域边界与职责划定

### 3.1 Domain A: 物理预处理域

- 输入：媒体文件；
- 输出：纯物理 `AudioChunk` 列表（不含说话人语义）；
- 职责：VAD、分诊、分离、LangID；
- 禁止：写入 `speaker_id/primary_speaker_id/speaker_embedding` 到 Chunk。

### 3.2 Domain B: 时间线域（新核心）

- 输入：分离后音频 + VAD 区间 + LangID；
- 输出：`SpeakerTimeline`；
- 职责：声纹特征、在线聚类、segmentation 融合、turn 生成；
- 禁止：直接驱动 Whisper 或后处理。

### 3.3 Domain C: 快流域

- 输入：`AudioChunk`；
- 输出：`PendingFastUnit`（草稿文本 + 词级时间）；
- 职责：低延迟草稿；
- 禁止：做说话人分组决策。

### 3.4 Domain D: Bridge 调度域

- 输入：`SpeakerTimeline` + `PendingFastUnit`；
- 输出：`TurnGroup`；
- 职责：单说话人组批、背压、flush；
- 禁止：聚类/分割算法内嵌。

### 3.5 Domain E: 慢流域

- 输入：`TurnGroup`；
- 输出：`SlowGroupResult`；
- 职责：Whisper 批识别；
- 禁止：跨 speaker 音频拼接。

### 3.6 Domain F: 后处理域（L2-L7）

- 输入：`PendingFastUnit + SlowGroupResult + SpeakerTimeline`；
- 输出：最终字幕段；
- 职责：对齐、注入、切分、输出；
- 禁止：回写上游调度策略。

### 3.7 Domain G: 声纹库域（SQLite）

- 输入：`SpeakerTimeline + Final SentenceSegment + 前端编辑指令`；
- 输出：`SpeakerProfileView + SubtitleSpeakerTrace`；
- 职责：任务级独立持久化、speaker 元数据维护、字幕追溯查询、前端可编辑回写；
- 禁止：直接调用推理模型或修改 Bridge/Slow 调度。

## 4.4 任务级独立声纹库（SQLite）

### 设计决策

1. 每个任务独立一个 SQLite 文件：`jobs/{job_id}/speaker_store.db`；
2. 复用现有 `sqlite3` 技术栈与 Repository 模式，不复用 `task_state.db` 的 schema；
3. 任务删除时随任务目录一并删除，天然实现隔离与回收；
4. 声纹库只存“结构真相”，不缓存模型对象。

### 建议新增文件

- `backend/app/services/speaker_store/speaker_store_repository.py`
- `backend/app/services/speaker_store/speaker_store_models.py`
- `backend/app/services/speaker_store/speaker_store_service.py`

### 表结构（目标态）

```sql
-- speaker 基础资料（前端可改）
CREATE TABLE speaker_profiles (
    speaker_id TEXT PRIMARY KEY,
    display_name TEXT NOT NULL,
    color_key TEXT NOT NULL,
    status TEXT NOT NULL,              -- candidate/confirmed/merged/unknown
    is_locked INTEGER NOT NULL DEFAULT 0,
    sample_count INTEGER NOT NULL DEFAULT 0,
    quality_score REAL NOT NULL DEFAULT 0,
    centroid_blob BLOB,
    created_at REAL NOT NULL,
    updated_at REAL NOT NULL
);

-- turn 与 speaker 的时轴绑定（系统写入）
CREATE TABLE turn_speaker_links (
    turn_id TEXT PRIMARY KEY,
    speaker_id TEXT NOT NULL,
    block_id TEXT NOT NULL,
    start REAL NOT NULL,
    end REAL NOT NULL,
    boundary_confidence REAL NOT NULL,
    source TEXT NOT NULL,
    updated_at REAL NOT NULL,
    FOREIGN KEY (speaker_id) REFERENCES speaker_profiles(speaker_id)
);

-- 字幕与 speaker/turn 的追溯绑定（系统写入+用户可改）
CREATE TABLE subtitle_speaker_links (
    sentence_index INTEGER PRIMARY KEY,
    turn_id TEXT,
    speaker_id TEXT NOT NULL,
    start REAL NOT NULL,
    end REAL NOT NULL,
    text_hash TEXT,
    binding_source TEXT NOT NULL,      -- auto/user
    updated_at REAL NOT NULL,
    FOREIGN KEY (speaker_id) REFERENCES speaker_profiles(speaker_id)
);

-- 用户编辑审计（前端改名/改色/重绑）
CREATE TABLE speaker_audit_logs (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    action TEXT NOT NULL,
    speaker_id TEXT,
    sentence_index INTEGER,
    payload_json TEXT,
    created_at REAL NOT NULL
);

CREATE INDEX idx_turn_speaker ON turn_speaker_links (speaker_id, start);
CREATE INDEX idx_subtitle_speaker ON subtitle_speaker_links (speaker_id, start);
```

### 读写原则

1. `SpeakerTimeline` 落库只写 `speaker_profiles + turn_speaker_links`；
2. L7 定稿时写 `subtitle_speaker_links`，形成字幕可追溯链；
3. 前端修改只改 `speaker_profiles` 和 `subtitle_speaker_links`，禁止改 `turn_speaker_links` 原始检测结果；
4. 每次用户修改写 `speaker_audit_logs`，便于回放与问题排查。

## 4.6 SQLite 统一管理策略（轻量可扩展）

### 结论

- 采用**专门模块统一管理 SQLite 基础能力**；
- 各业务域继续通过各自 Repository 管理表和 SQL；
- 禁止业务服务直接调用 `sqlite3`。

### 最小实现（不过度设计）

建议新增目录：`backend/app/services/storage/`，仅提供三类基础能力：

1. `sqlite_engine.py`
   - 统一连接创建（`row_factory`、`foreign_keys`、`WAL`、`busy_timeout`）
2. `sqlite_tx.py`
   - 统一事务上下文（`BEGIN IMMEDIATE`、提交、回滚）
3. `sqlite_migrator.py`
   - 统一 schema 版本检查与增量迁移入口

### 边界约束

1. 域 Repository（`task_state` / `runtime_checkpoint` / `speaker_store`）只依赖 storage 基础模块；
2. 域间不共享表，不做跨域 Join；
3. 新增域时只需新增一个 Repository + migration 文件即可快速扩展。

## 5. 模式适配（统一策略层）

统一新增 `ModePolicy`（建议放在 `backend/app/pipelines/mode_policy.py`）：

- `fast_only`
- `smart_patch`
- `dual_full`

### 5.1 fast_only

- 开启：Fast
- 关闭：S-Epoch / W-Epoch
- 输出：快流直接进入 L6/L7

### 5.2 smart_patch

- 开启：Fast + 局部 S-Epoch + 局部 W-Epoch
- 作用范围：仅风险窗口（超长句/低置信/多人冲突）

### 5.3 dual_full

- 开启：Fast + 全量 S-Epoch + 全量 W-Epoch
- 作用范围：全量 turn

### 5.4 无 GPU 强制回退

- 强制模式：`fast_only`；
- 强制禁用：Pyannote segmentation；
- 默认不跑 Whisper（除非用户显式打开 CPU 复核）。

### 5.5 Pyannote segmentation 纳入统一模型管理

- 必须纳入 `ModelManagerV2` 的统一注册、加载、驻留与驱逐；
- 禁止在业务层直接 `from_pretrained` 长驻，避免绕开显存预算；
- 通过 runtime 配置显式声明 `segmentation` 模型与设备策略；
- 与 `S-Epoch/W-Epoch` 调度保持一致：同一时刻仅允许一类重模型占用 GPU。

## 6. S-Epoch / W-Epoch 与快流协同时序

### 6.1 启动逻辑

`Preprocess 完成` 后：

1. Fast Loop 立即启动（草稿可见）；
2. S-Epoch 启动（生成 `SpeakerTimeline`）；
3. S-Epoch 完成后 Bridge 才能产生 `TurnGroup`；
4. W-Epoch 消费 `TurnGroup`；
5. 每个慢流组完成即触发 L2-L7 增量定稿。

### 6.2 快流产物消费规则

- S-Epoch 未完成期间：快流产物进入 `DraftCache`；
- Draft 可推送前端，但不触发慢流组批；
- Timeline Ready 后，按 turn 映射消费缓存。

### 6.3 对齐触发时机

- 非“整块完成后统一对齐”；
- 采用“**慢流组完成即对齐**”的批级增量触发。

## 7. 抗幻觉组批与 flush 机制（必须落地）

### 7.1 核心约束

1. 一个 `TurnGroup` 只允许一个 `speaker_id` 的目标音频；
2. 不允许跨 speaker 音频拼接；
3. 跨 speaker 仅允许文本上下文进入 `prompt_text`。

### 7.2 Flush 条件（去除语义歧义）

- `min_audio_sec` 达标（如 4~8 秒）；
- 或 `min_token_count` 达标；
- 或 `max_wait_sec` 超时；
- 或 `language_change`；
- 或 `tail_idle_sec`（短尾句强制出包）；
- 或 `eof_flush`（任务结束强制出包）。

### 7.3 极端场景处理

- **短句且后续无语音**：`tail_idle_sec` / `eof_flush` 强制出包，不等待；
- **同人长间隔发言**：超过 `long_pause_cut_sec` 必断 turn，不跨间隔拼音频。

## 8. 聚类准确性改造（解决“3人识别成10人”）

当前 `speaker_cluster_service.py` 的“最近质心+阈值”策略保留思路，但必须升级为三层约束：

### 8.1 新人确认机制

- 新 speaker 进入 `candidate` 状态；
- 仅当满足 `min_support_turns` 且 `min_total_duration` 才提升为 `confirmed`；
- 候选态不参与 Bridge 硬切分。

### 8.2 质量门控

- 低质量特征（低 SNR、过短片段、重叠片段）不允许创建新 speaker；
- 仅允许匹配已有 speaker 或标记 `unknown`。

### 8.3 增量合并

- 每 N 个 turn 执行 centroid merge；
- 相似 speaker 自动合并并记录 `speaker_remap`；
- 防止 ID 不断膨胀。

## 10.4 断点与缓存统一重构蓝图（新增）

### 10.4.1 总体策略：双层断点

1. **产物层（Artifact Layer）**：继续保留 `jobs/{job_id}` 文件缓存（音频分离产物、预处理缓存、调试文件）；
2. **状态层（State Layer）**：新增 `jobs/{job_id}/runtime_state.db`，记录最小可恢复单元与队列快照；
3. **镜像层（可选）**：`checkpoint.json` 仅作可读快照/兼容镜像，不再作为恢复真相源。

### 10.4.2 预处理域改造策略

- 结论：**保留现有 jobs 目录缓存 + 重构状态断点**；
- VAD/分诊/分离/LangID 产物继续走文件缓存，不迁移到 SQLite；
- 断点改为单元化提交：`vad_chunk` / `triage_chunk` / `separation_chunk` / `langid_chunk`；
- 恢复优先从 `runtime_state.db` 读取进度，再命中产物缓存，避免重复计算。

### 10.4.3 快流/慢流/后处理改造策略

- 结论：**彻底重构暂停-恢复控制面**；
- 从“捕获暂停后继续排空队列”改为“完成当前单元后立即暂停”；
- `Slow` 最小单元为 `turn_group`，`Finalize` 最小单元为 `finalize_batch`；
- 恢复时按 `last_committed_unit` 回放，不允许跨单元重算。

### 10.4.4 建议新增文件（断点域）

## 12. 测试与验收标准

### 12.1 功能验收

1. Whisper 批次音频不得跨 speaker；
2. speaker 误分裂率显著下降（3 人场景不再膨胀为 10+）；
3. 短尾句不丢失；
4. 长间隔不跨段拼接；
5. L6 切分不跨 turn。
6. 不同任务声纹库物理隔离（互不可见）；
7. 前端修改 speaker 名称/颜色后可立即追溯到字幕。
8. pause 请求在单元边界快速生效，不依赖全队列排空。

### 12.2 性能验收

1. 8GB GPU 不出现 S/W 并载 OOM；
2. 首条草稿延迟不劣化；
3. 单元测试保持每批次执行在可控时长（建议 < 60s）。
4. pause 响应延迟和 resume 恢复耗时可观测且稳定。

### 12.3 稳定性验收

1. 任一 phase 可独立跑通并回退；
2. 无 GPU 下自动走 `fast_only` 默认路径；
3. 不依赖运行时兼容分支。
4. 任意时刻可基于 `speaker_audit_logs` 回放用户改动。
5. 崩溃恢复后重算范围被限制在“最后未提交单元”。
