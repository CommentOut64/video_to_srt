# 转录与编辑解耦及旧任务兼容重构方案（v3.2.3）

> Type: Architecture | Status: Draft
> Version: V3.2.4+dev.20260222.01
> Scope: 转录链路与编辑链路解耦、能力可组合调用、旧任务全量兼容、Full/Lite 共库建模
> Non-Goal: 本文不包含 ASR 模型算法升级细节，不包含 UI 视觉重设计，不采用长期 Lite 独立分支

## 1. Summary

* **Goal**: 将现有 `job_id` 单体任务模型重构为“Project + Run + SubtitleDoc + MediaAsset”分层架构，使用户可自由选择转录、编辑、预处理能力组合，并保证旧任务无需重跑转录即可完整编辑、预览、导出。
* **核心策略**:
  * 以 `Project` 作为编辑真相源，以 `Run` 作为执行真相源。
  * 在解耦阶段直接落地 Lite-ready 契约，避免后续二次改 API/Store/路由。
  * 使用 `flavor` 枚举统一 Full/Lite：后端 `ANCHORFLUX_FLAVOR=full|lite`，前端 `VITE_APP_FLAVOR=full|lite`。
  * 兼容读取历史布尔开关：`ANCHORFLUX_LITE`、`VITE_LITE_MODE`，内部统一折算为 `flavor`。
  * 通过“旧任务投影层”将历史 `job` 映射为新 `Project(legacy)`。
  * 保留旧 API 入口，内部转发至新服务，分阶段替换前端调用。
  * 先兼容再切主链，确保可灰度、可回滚。

## 2. Diagram

* `Task(job)` -> `LegacyProjectionService` -> `Project(mode=legacy, flavor=full)` -> `SubtitleDoc + MediaAsset` -> `Editor`
* `Project(flavor=full)` -> `RunService.create_run(capability)` -> `Run` -> `Artifact` -> `Project`/下载端
* `Project(flavor=lite)` -> `ProjectImportService` -> `SubtitleDoc + MediaAsset` -> `Editor`（不触发转录链路）
* `SSE: run:{run_id}`（进度/阶段）与 `SSE: project:{project_id}`（字幕/编辑）双通道并行；Lite 可仅订阅 `project` 通道
* `build(full|lite)` -> `vite tree-shaking + backend conditional load + electron profile prune`

## 4. 背景与问题归并

### 4.1 当前核心耦合

1. 路由层仅支持 `/editor/:jobId`，编辑器生命周期和转录任务强绑定。
2. 字幕编辑 API 全部依赖 `job_id + sentence_index`，缺少独立字幕文档实体。
3. 波形交互与播放控制受 `isVideoReady` 拦截，无媒体时无法完整编辑。
4. SSE 以任务频道为唯一通道，编辑态与运行态混杂。
5. 频谱分诊/人声分离无法作为独立能力调用与导出。
6. 当前缺少统一 flavor 约束，Lite 若后置适配会导致二次改动与兼容面膨胀。

### 4.2 用户目标

1. 仅编辑模式：导入“已有字幕 + 视频/音频”即可工作，不经过转录。
2. 部分能力模式：仅执行分诊、分离、纯人声导出。
3. 旧任务兼容：历史任务不重跑转录，仍可完整编辑、预览、导出。
4. Full/Lite 共用同一套领域模型与存储格式，差异只体现在能力集合、界面入口和打包内容。

## 5. 目标架构全景

### 5.1 领域模型拆分

1. `Project`
   * 编辑工作区，聚合 `SubtitleDoc`、`MediaAsset`、`Run` 引用。
   * 支持 `mode=normal|legacy` 与 `flavor=full|lite`。
   * 固化 `capability_snapshot`，确保项目生命周期内能力边界一致。
2. `SubtitleDoc`
   * 字幕真值文档，使用稳定 `segment_id`，不再依赖任务运行索引。
   * 支持版本快照、编辑标记、删除墓碑。
   * 增加 `source_type=transcribe|import|legacy` 便于追踪与回滚。
3. `Run`
   * 一次能力执行实例，包含状态、阶段、日志、产物索引。
   * 创建前执行 `flavor x capability` 白名单校验。
4. `MediaAsset`
   * 视频、音频、peaks、proxy、thumbnails 等资产统一注册。
   * Lite 模式下 `proxy` 为可选资产，不作为编辑前置。
5. `Artifact`
   * 运行产物（如 `vocals.wav`、`triage_report.json`、`srt/ass`）。

### 5.2 能力目录（Capability Catalog）

1. `transcribe.full`
2. `transcribe.fast_only`
3. `audio.spectral_triage`
4. `audio.vocal_separation`
5. `audio.clean_vocals_export`
6. `media.prepare_preview`
7. `subtitle.import_export`

能力矩阵（强约束）：

| capability | full | lite |
|---|---|---|
| `transcribe.full` | 允许 | 禁用 |
| `transcribe.fast_only` | 允许 | 禁用 |
| `audio.spectral_triage` | 允许 | 可选（按发行策略决定） |
| `audio.vocal_separation` | 允许 | 禁用 |
| `audio.clean_vocals_export` | 允许 | 禁用 |
| `media.prepare_preview` | 允许 | 允许（仅补齐编辑所需资产） |
| `subtitle.import_export` | 允许 | 允许 |

说明：

1. Lite 下调用禁用能力统一返回 `422 capability_not_allowed`。
2. 能力矩阵由后端守卫执行，前端仅做体验层禁用，不承担安全边界。

### 5.3 双通道事件模型

1. `run:{run_id}`
   * `run.status_changed`
   * `run.phase_progress`
   * `run.artifact_ready`
2. `project:{project_id}`
   * `project.subtitle.updated`
   * `project.subtitle.added`
   * `project.subtitle.deleted`
   * `project.media.updated`

事件契约补充：

1. 所有事件统一携带 `seq`、`updated_at`、`project_id`、`owner`。
2. Lite 导入编辑链路可不产生 `run:*` 事件，前端需允许“仅 project 通道”稳定运行。

## 8. 旧任务兼容方案（完整）

### 8.1 兼容目标

1. 历史任务零重跑转录。
2. 完整支持编辑、预览、导出。
3. 保留旧入口与旧链接可用。
4. 旧任务迁移后与 Full/Lite 共用同一 `Project/SubtitleDoc` 数据形态。

### 8.2 映射与迁移

1. 新增映射存储：`legacy_task_map(job_id, project_id, migrated_at, status)`。
2. 懒迁移触发点：
   * 打开旧编辑路由。
   * 调用旧字幕编辑 API。
   * 调用旧媒体 API 且无映射时。
3. 首次迁移流程：
   * 创建 `Project(mode=legacy, flavor=full)`。
   * 恢复 `SubtitleDoc`（见 8.3）。
   * 挂载旧任务媒体资产。
   * 回写映射并返回 `project_id`。
4. Lite 打开 legacy 项目时：
   * 允许编辑/预览/导出。
   * 禁止发起转录类 Run，返回 `422 capability_not_allowed`。

### 8.3 字幕恢复优先级

1. `subtitle_edits.json + checkpoint/transcription_text`（最完整）
2. `checkpoint/transcription_text`（次优）
3. `.srt` 文件（兜底）

恢复时执行：

1. 合并 `is_modified/original_text`。
2. 应用 `deleted_indices`。
3. 对无 `segment_id` 的旧句生成稳定 ID。
4. 写入 `source_type=legacy` 与 `origin_sentence_index`。

### 8.4 媒体兼容策略

1. 直接复用旧 `job_dir` 中已有资产（video/audio/peaks/proxy）。
2. 若缺 `audio.wav` 或 `peaks`，仅触发 `media.prepare_preview` 运行补齐。
3. 若缺视频，编辑器进入“纯字幕模式”，保留字幕时间轴和导出能力。
4. Lite 不以 proxy 作为编辑前置条件，避免触发重媒体链路。

### 8.5 旧 API 兼容桥接

1. 保留接口形态：
   * `/api/transcription-text/{job_id}`
   * `/api/jobs/{job_id}/subtitles/*`
   * `/api/media/{job_id}/*`
2. 内部流程：
   * 先 resolve `project_id`。
   * 转发到新服务。
   * 返回旧格式响应（字段别名适配）。
3. 错误码收敛：
   * `409 legacy_transcription_conflict`
   * `422 capability_not_allowed`
   * `404 legacy_mapping_not_found`

### 8.6 写入与回滚策略

1. 过渡期双写：
   * 主写新 `SubtitleDoc`。
   * 同步更新旧 `.srt`（及必要旧编辑文件）。
2. 回滚开关：
   * 配置项 `legacy.adapter.enabled`。
   * 关闭后回到旧读写路径。
3. 非破坏保障：
   * 旧文件不删除，仅标记迁移状态。
4. flavor 变更策略：
   * 项目数据不随 flavor 分叉。
   * 仅能力入口与界面入口随 flavor 收敛。

## 9. 分阶段实施计划

### M0 基线冻结

1. 冻结当前接口行为与关键路径测试。
2. 建立 `legacy_task_map` 数据表与诊断日志。
3. 冻结 flavor 契约（变量名、取值、别名兼容、错误码）。

### M1 后端骨架

1. 落地 `Project/Run/SubtitleDoc` 模型与服务。
2. 建立 `legacy_projection_service` 与 resolve API。
3. 落地 `/api/projects/import` 与能力守卫。

### M2 兼容桥接

1. 旧字幕与媒体 API 内部转发。
2. 完成旧任务懒迁移闭环。
3. 验证 legacy 在 Lite 下的“可编辑不可转录”约束。

### M3 前端切换

1. 编辑器切换 `project_id` 主路径。
2. `job_id` 路由 resolve 后重定向。
3. 完成 flavor UI 入口收敛（含 `/import`）。

### M4 能力解耦

1. 暴露独立能力运行 API。
2. 前端支持“只分诊/只分离/仅导出纯人声”。
3. 按能力矩阵完成 Full/Lite 差异收敛。

### M5 收敛清理

1. 将 `job_id` 从编辑主链移出，仅保留兼容适配。
2. 清理无用分支并补齐文档与验收报告。
3. 清理散落的临时 `isLite` 分支判断，统一走 flavor 配置。

## 10. 测试与验收标准

### 10.1 单元测试

1. 旧任务投影正确性（映射稳定、重复调用幂等）。
2. 字幕恢复优先级与字段合并正确性。
3. 旧 API 适配字段一致性。
4. flavor 解析正确性（`ANCHORFLUX_FLAVOR` 与 `ANCHORFLUX_LITE` 兼容）。
5. capability 守卫矩阵正确性（full/lite 交叉断言）。

### 10.2 集成测试

1. 旧任务首次打开 -> 自动迁移 -> 可编辑 -> 可导出。
2. 仅字幕导入项目（无视频）可完整编辑并导出。
3. 媒体缺失场景自动补齐，不触发转录。
4. 独立能力运行生成产物并可下载。
5. Lite 启动检查：不加载转录重依赖，不注册转录重路由。
6. Lite 调用禁用能力返回 `422 capability_not_allowed`。

### 10.3 用户验收

1. 历史任务编辑体验不退化。
2. 无媒体时字幕编辑无阻断。
3. 导出内容与编辑器当前状态一致。
4. Lite 路径可稳定完成“导入 -> 编辑 -> 导出”闭环。

CI 守卫：

1. Lite 构建产物依赖检查：不得包含 `torch/onnxruntime/faster-whisper/pyannote/demucs`。
2. Lite API 冒烟：`/api/projects/import` 可用，禁用能力返回码正确。

## 11. 风险与缓解

1. 风险：旧索引与新 `segment_id` 映射错误导致编辑错位。
   * 缓解：迁移时保存 `origin_sentence_index`，加入校验与回滚。
2. 风险：双写期间新旧数据不一致。
   * 缓解：以新文档为真值，旧文件异步校验并告警。
3. 风险：前端事件通道改造引入状态抖动。
   * 缓解：事件附加 `seq/updated_at`，前端按序应用。
4. 风险：flavor 漏判导致 Lite 暴露重能力。
   * 缓解：后端统一 capability guard，前端仅作展示层禁用。
5. 风险：条件注册遗漏导致 Lite 启动仍加载重依赖。
   * 缓解：启动自检 + CI import 守卫 + 路由白名单校验。
6. 风险：tree-shaking 未生效导致前端冗余体积。
   * 缓解：构建后产物扫描与 bundle 对比阈值告警。

## 12. 发布与回滚策略

1. 灰度发布：
   * `feature.project_mode` 控制新路径比例。
   * `feature.flavor_guard` 控制 capability 守卫强制级别。
2. 快速回滚：
   * 关闭 `feature.project_mode` 与 `legacy.adapter.enabled` 组合开关回退旧主链。
3. 数据安全：
   * 迁移不删除旧任务目录，回滚后可直接恢复旧读取。
4. 分支策略：
   * 不维护长期 Lite 独立分支。
   * 仅在发布窗口使用短生命周期 `release/*` 分支做冻结与热修。
