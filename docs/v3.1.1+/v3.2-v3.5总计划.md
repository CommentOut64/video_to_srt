### AnchorFlux 演进路线图 (v3.2 - v3.5)

#### 📅 Phase v3.2: 基础设施重构 (Infrastructure & Decoupling)

代号: Foundation (地基)

核心目标: 解决“模型管理混乱”和“编辑器状态耦合”两大痛点，为后续引入多模型和复杂逻辑扫清障碍。不涉及核心识别算法变更。

- **1. 统一模型管理系统 (Unified Model Governance)**
  - **重构**: 废弃散落在各个 Service 里的模型加载代码。
  - **新增**: `ModelManager V2` (单例服务)。
  - **功能**: 统一管理 Whisper, SenseVoice, Demucs, Yamnet, Punctuation 等所有模型的下载、校验、版本控制。
  - **关键特性**: **显存预算池 (VRAM Budget Pool)** —— 动态卸载不用的模型（如跑 Whisper 时卸载 Punctuation），防止 OOM。
- **2. 编辑器状态解耦 (State Decoupling)**
  - **重构**: 前端 Pinia Store 拆分。将 `TranscriptState` (字幕数据) 与 `MediaState` (视频/波形) 彻底分离。
  - **功能**: 支持无视频/无波形模式下的字幕编辑。
  - **新增**: **项目导入功能** (支持导入 `.srt/.ass` + 视频文件继续编辑)。
- **⚠️ 兼容性警告**:
  - `config.json` 结构将大改（模型路径配置变更）。
  - 前端本地缓存的数据结构将不兼容旧版本。

------

#### 📅 Phase v3.3: 神经中枢与语义流 (The Neural Bridge)

代号: Precision (精准)

核心目标: 彻底解决幻觉和分句问题。引入“预防式分诊”和“标点模型”。

- **1. 预防式分诊 (Strict Spectral Triage)**
  - **机制**: 废弃“后置熔断”。在 `PreprocessingPipeline` 引入 **Yamnet/频谱分析**。
  - **流程**: `Audio` -> `SpectralGate` -> (如果 Dirty) `Demucs` -> `SenseVoice`。
  - **元数据流**: 音频块携带 `QualityTags` (Metadata) 流向下游，指导 Bridge 决策。
- **2. 神经中枢 (Bridge Controller)**
  - **架构**: 建立 `Bridge Layer`。`FastWorker` 和 `SlowWorker` 退化为纯执行器。
  - **路由**: 根据 Yamnet 的标签，决定是否信任 SenseVoice 的空输出。
  - **语言探测**: 引入轻量级 Probe 获取准确语言，路由到不同的后处理模块。
- **3. 标点驱动分句 (Punctuation-Driven Segmentation)**
  - **新增**: `PunctuationService` (FunASR/CT-Transformer)。
  - **逻辑**: 替代 Regex。`SenseVoice Raw` -> `Add Punctuation` -> `Split by Sentence`。
  - **语义缓冲**: 基于标点切分出的完整句子构建 `Semantic Buffer`，喂给 Whisper。

------

#### 📅 Phase v3.4: 质量感知与效率 (Perception & Throughput)

代号: Velocity (速度)

核心目标: 在准确率稳固的基础上，提升吞吐量和鲁棒性。

- **1. 乱序并行执行 (Out-of-Order Execution)**
  - **优化**: 将 `FastWorker` 改造为并行池。
  - **组件**: 实现 `SequencedQueue`，允许短句先跑完，但在提交给 Bridge 时按时间戳重新排序。
- **2. NISQA 质量评分**
  - **新增**: 引入 NISQA 模型。
  - **用途**: 对 Whisper 的最终输出进行质量打分。如果音频质量极差（NISQA 分低）且 Whisper 置信度低，UI 标记为“需人工确认”，不再盲目自信。

------

#### 📅 Phase v3.5: 认知智能 (Cognitive Intelligence)

代号: Insight (洞察)

核心目标: 引入 LLM 进行最后一步的润色，不干扰声学层。

- **1. LLM 审阅者 (The Reviewer)**
  - **定位**: 纯后处理。
  - **功能**: 全文逻辑校对、多语言翻译、重点摘要。
  - **策略**: 绝不触发“重新转录”，只做文本层面的修补。

### 版本依赖与升级路径

| **版本** | **依赖关系** | **关键产出**                   | **风险等级**               |
| -------- | ------------ | ------------------------------ | -------------------------- |
| **v3.2** | 独立         | 模型管理器、导入功能、前端解耦 | 🔥 High (配置/数据结构破坏) |
| **v3.3** | 依赖 v3.2    | 标点模型、Yamnet分诊、Bridge层 | ⭐ Medium (逻辑复杂)        |
| **v3.4** | 依赖 v3.3    | NISQA、乱序队列                | 📉 Low (性能优化)           |
| **v3.5** | 依赖 v3.3    | LLM 集成                       | 📉 Low (插件式功能)         |

### 为什么这样安排更合理？

1. **先安家 (v3.2)**：如果现在不统一管理模型，到了 v3.3 引入 Yamnet 和标点模型时，代码里的模型加载逻辑会乱成一锅粥，显存甚至会爆炸。
2. **后治水 (v3.3)**：有了模型管理器，我们才能从容地加载 Yamnet 做分诊，加载 FunASR 做标点。这是解决幻觉的根本。
3. **再提速 (v3.4)**：乱序执行很快，但如果模型还在幻觉，跑得越快错得越多。所以必须等 v3.3 稳定了再做。
