### 步骤 1: 构建“云端数据流”生成器

**文件:** `tools/data_streamer.py`

这个模块负责从 Hugging Face 实时拉取噪声音频，并不占用硬盘空间。我们将使用 `mathias/musan` 数据集。

```python
import torch
import torchaudio
from datasets import load_dataset
import logging

logger = logging.getLogger("DataStreamer")

class CloudNoiseStreamer:
    def __init__(self, buffer_size=50):
        self.buffer_size = buffer_size
        self.sr = 16000  # Brouhaha 需要 16k
        self._iterator = None
        
    def _init_stream(self):
        """初始化 HF 流式连接"""
        print("正在连接 Hugging Face (mathias/musan)...")
        # streaming=True 是关键，不下载，只读取
        try:
            self.dataset = load_dataset("mathias/musan", split="train", streaming=True)
            self._iterator = iter(self.dataset)
        except Exception as e:
            print(f"连接 HF 失败: {e}。请检查网络或 HF_TOKEN。")
            raise

    def get_noise_batch(self, batch_size=5):
        """获取一批噪声音频（张量）"""
        if not self._iterator:
            self._init_stream()
            
        noises = []
        while len(noises) < batch_size:
            try:
                item = next(self._iterator)
                # MUSAN 包含 music, noise, speech。我们需要 music 和 noise
                # 这里根据路径简单过滤 (metadata 视具体 dataset 结构而定)
                # 假设 item['audio']['array'] 是波形
                
                # 转换为 Tensor
                wav = torch.tensor(item['audio']['array']).float()
                src_sr = item['audio']['sampling_rate']
                
                # 重采样到 16k
                if src_sr != self.sr:
                    resampler = torchaudio.transforms.Resample(src_sr, self.sr)
                    wav = resampler(wav)
                
                # 确保是单声道
                if wav.ndim > 1:
                    wav = wav.mean(dim=0)
                
                # 过滤太短的片段 (<3秒)
                if wav.shape[0] < self.sr * 3:
                    continue
                    
                noises.append(wav)
                
            except StopIteration:
                self._init_stream() # 循环播放
                
        return noises

# 单元测试
if __name__ == "__main__":
    streamer = CloudNoiseStreamer()
    batch = streamer.get_noise_batch(2)
    print(f"成功获取 {len(batch)} 个云端噪声片段")

```

### 步骤 2: 构建“动态混音实验室”

**文件:** `tools/audio_mixer.py`

这个模块负责将你本地的一个“纯净人声”与云端拉下来的噪声，按照指定的 **SNR (信噪比)** 进行数学混合。这是生成 Ground Truth 的核心。

```python
import torch
import random

def calculate_rms(audio):
    """计算均方根能量"""
    return torch.sqrt(torch.mean(audio**2) + 1e-9)

def mix_audio(clean_speech: torch.Tensor, noise: torch.Tensor, target_snr_db: float):
    """
    核心算法：根据目标 SNR 混合人声和噪声
    Returns: 
        mixed_audio: 混合后的音频
        masking_level: 一个 0-1 的值，表示掩盖程度（用于验证）
    """
    # 1. 长度对齐：将噪声切割或循环以匹配人声
    if noise.shape[0] < clean_speech.shape[0]:
        repeat_times = clean_speech.shape[0] // noise.shape[0] + 1
        noise = noise.repeat(repeat_times)
    noise = noise[:clean_speech.shape[0]]
    
    # 2. 计算能量
    speech_rms = calculate_rms(clean_speech)
    noise_rms = calculate_rms(noise)
    
    # 3. 计算目标噪声增益
    # SNR = 20 * log10(Speech / Noise)
    # Noise_Target = Speech / 10^(SNR/20)
    target_noise_rms = speech_rms / (10 ** (target_snr_db / 20))
    
    gain = target_noise_rms / (noise_rms + 1e-9)
    
    # 4. 混合
    mixed = clean_speech + noise * gain
    
    # 5. 归一化防爆音
    max_val = torch.max(torch.abs(mixed))
    if max_val > 1.0:
        mixed = mixed / max_val
        
    return mixed

```

### 步骤 3: 构建“全自动调参引擎”

**文件:** `tools/auto_tune_brouhaha.py`

这是大脑。它使用 `Optuna` 自动寻找最佳的 `SNR_THRESHOLD`。你需要准备一个本地的纯净人声文件（`clean_anchor.wav`）作为基准。

```python
import optuna
import torch
import torchaudio
import logging
from data_streamer import CloudNoiseStreamer
from audio_mixer import mix_audio
from pyannote.audio import Model, Inference

# ---------------- 配置区域 ----------------
CLEAN_SPEECH_PATH = "assets/clean_anchor.wav" # 找一个清晰的单人说话录音放这里
N_TRIALS = 50       # 自动尝试多少次参数组合
SAMPLE_COUNT = 20   # 每一轮测试用多少条音频验证
# ----------------------------------------

# 初始化模型 (Brouhaha)
print("加载 Brouhaha 模型中...")
try:
    # 假设你已经能加载模型，如果不能联网，请换成本地路径
    model = Model.from_pretrained("pyannote/brouhaha", use_auth_token="YOUR_HF_TOKEN")
    inference = Inference(model)
except Exception as e:
    print("模型加载失败，请配置 Token")
    exit(1)

# 初始化数据流
streamer = CloudNoiseStreamer()
clean_speech, sr = torchaudio.load(CLEAN_SPEECH_PATH)
if sr != 16000:
    resampler = torchaudio.transforms.Resample(sr, 16000)
    clean_speech = resampler(clean_speech)
clean_speech = clean_speech.mean(dim=0) # 转单声道

def run_brouhaha_prediction(audio_tensor):
    """运行 Brouhaha 推理"""
    # 这是一个简化 wrapper，实际根据你的集成代码来
    # Pyannote Inference 通常接受文件路径或 Tensor
    # 这里为了速度，我们假设 inference 支持 tensor (需转换形状)
    input_tensor = audio_tensor.unsqueeze(0).unsqueeze(0) # (1, 1, T)
    output = model(input_tensor)
    
    # 获取平均 SNR (Brouhaha 输出是帧级别的，取平均)
    # output['snr'] shape: (Batch, Frames)
    pred_snr = output['snr'].mean().item()
    return pred_snr

def objective(trial):
    """Optuna 的目标函数"""
    
    # 1. 让 AI 猜一个阈值
    suggested_threshold = trial.suggest_float("snr_threshold", 5.0, 25.0)
    
    total_penalty = 0
    
    # 2. 动态生成验证集 (包含好坏两种情况)
    noises = streamer.get_noise_batch(SAMPLE_COUNT)
    
    for i, noise in enumerate(noises):
        # 随机决定生成一个 "需要分离" 还是 "不需要分离" 的样本
        is_hard_case = (i % 2 == 0) 
        
        if is_hard_case:
            # 生成难例 (SNR = 5dB)，人声被掩盖
            # Ground Truth: 应该分离 (Separation Needed)
            target_snr = 5.0
            should_separate = True
        else:
            # 生成易例 (SNR = 25dB)，轻微噪音
            # Ground Truth: 应该直通 (Pass)
            target_snr = 25.0
            should_separate = False
            
        # 混合
        mixed_wav = mix_audio(clean_speech, noise, target_snr)
        
        # 预测
        pred_snr = run_brouhaha_prediction(mixed_wav)
        
        # 决策逻辑 (模拟 AnchorFlux)
        will_separate = pred_snr < suggested_threshold
        
        # --- 计算惩罚 (Loss) ---
        if should_separate and not will_separate:
            # 漏报 (False Negative): 最严重的错误！
            # 实际上很吵，但我们没分离，导致字幕全错。
            # 惩罚系数: 10
            total_penalty += 10.0
            
        elif not should_separate and will_separate:
            # 误报 (False Positive): 性能浪费。
            # 实际上很安静，但我们分离了，浪费了 GPU 时间。
            # 惩罚系数: 1 (我们宁愿慢一点，也不要错)
            total_penalty += 1.0
            
    return total_penalty

# 3. 开始搜参
if __name__ == "__main__":
    print("🚀 开始全自动搜参...")
    study = optuna.create_study(direction="minimize")
    study.optimize(objective, n_trials=N_TRIALS)
    
    print("\n" + "="*40)
    print(f"🎉 最佳结果: Penalty = {study.best_value}")
    print(f"✅ 最佳 SNR 阈值: {study.best_params['snr_threshold']:.2f} dB")
    print("="*40)
    print("请将此数值填入 backend/app/core/thresholds.py")

```

### 核心优势

* **无需下载 11GB 数据**：利用带宽实时流式加载，跑完即焚。
* **对抗真实场景**：通过 `mix_audio`，你是用数学上绝对精准的 SNR (Ground Truth) 去“考”模型，而不是靠人耳听。
* **业务导向**：我们在 `objective` 函数中定义了 `漏报惩罚=10`，`误报惩罚=1`。这完美符合 AnchorFlux **“保质量优先，兼顾速度”** 的工程原则。

在你的 AnchorFlux 架构中，引入 **Brouhaha** 后的自动调参流水线，其核心目标是为“分诊系统”寻找**物理指标与识别质量之间的平衡点**。

具体来说，这套流水线主要针对以下三类关键参数：

### 1. 核心决策阈值 (Decision Thresholds)

这是最直接影响系统行为的参数，决定了哪些音频块（Chunk）需要被送入耗时且沉重的人声分离（Demucs）流程。

* **`SNR_THRESHOLD` (信噪比阈值)**：
* **含义**：判断环境有多“脏”的红线。
* **调参目标**：寻找一个数值（例如 14.5dB）。如果当前音频 SNR 低于此值，说明人声可能被掩盖，必须分离。
* **自动优化逻辑**：如果你设置得太高，系统会频繁触发 Demucs，导致处理变慢；设置太低，Whisper 会因为噪音出现幻觉。自动调参就是要在保证 WER（词错误率）不上升的前提下，尽可能调低这个阈值以节省算力。


* **`C50_THRESHOLD` (混响/清晰度阈值)**：
* **含义**：判断房间“空旷感”或“共振峰模糊”的指标。
* **调参目标**：针对你提到的“能量分布均匀、机械感”问题。当 C50 低于某个值时，说明混响太重，需要通过 Demucs 增强对比度。



### 2. 频谱分诊权重 (Spectral Triage Weights)

由于你不仅有 Brouhaha，可能还保留了 YAMNet 或 Librosa 的对比度分析，流水线会调整不同维度的**投票权重**。

* **`MUSIC_WEIGHT` vs `SNR_WEIGHT**`：
* **场景**：如果一段音频 SNR 很低（很吵），但 PANNs/YAMNet 没检测到音乐（Music Score 极低）。
* **调参目标**：自动确定当“背景是纯底噪（风扇声）”而非“音乐”时，是否依然需要触发 Demucs。系统会根据测试集的表现，自动决定谁的“话语权”更大。



### 3. ASR 稳定性参数 (ASR Robustness Parameters)

这些参数位于识别层，用于在“分诊结果”不确定时做最后的兜底。

* **`CONFIDENCE_MIN_THRESHOLD` (识别置信度熔断线)**：
* **含义**：Whisper 返回的 `avg_logprob` 达到多少时，我们才信任这个“直通”的结果。
* **调参目标**：如果自动调参发现即便 SNR 很高，但在某些特定背景下识别置信度依然很低，它会建议拉高这个熔断阈值，迫使系统进入“回溯（Backtracking）”模式，重新分离后再转录。



### 4. 性能与功耗平衡系数 (Performance-Efficiency Trade-off)

这是你在 `Optuna` 损失函数中定义的“价值观”。

* **`TIME_PENALTY_FACTOR` (耗时惩罚系数)**：
* **调参目标**：告诉 AI 你有多在乎速度。
* 如果你设置系数为 `10`，AI 找出的参数会非常“吝啬”使用 Demucs，只有极烂的音频才分离。
* 如果你设置系数为 `0.1`，AI 会变成“质量狂”，只要有一丁点噪音就去跑分离。



### 总结：调参的最终产物

当你跑完这个流水线，你得到的不是一堆复杂的代码，而是 `backend/app/core/thresholds.py` 中的几个**神奇常数**：

```python
# 经过 Optuna 50 轮迭代后的“最优解”
BROUHAHA_CONFIG = {
    "snr_threshold": 13.82,  # 自动算出：低于 13.82dB 分离效果最好
    "c50_threshold": 22.5,   # 自动算出：针对混响的敏感度
    "music_bias": 1.2        # 自动算出：当检测到音乐时，SNR 阈值自动放宽 1.2dB
}

```

**为什么这很重要？**
因为**人耳是会疲劳的**，你手动调 5 次就烦了，而且很难判断 15dB 和 14dB 的细微差别。**自动调参流水线是用“词错误率”作为唯一真理，帮你把系统的性能榨干到极限。**
