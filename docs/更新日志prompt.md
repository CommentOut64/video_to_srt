# Context

这是一个名为 "AnchorFlux" 的本地视频自动字幕生成工具，集成了 Whisper 和 SenseVoice 模型，前后端分离架构（Vue3 + FastAPI）。

# Input Data

从指定的分支或者commit范围中获取所有commit

# Workflow & Constraints (必须严格遵守)

1. **数据清洗 (Filtering)**：
   - **剔除**：直接忽略 `docs:`、`chore:`、`style:`、`ci:` 开头的提交。
   - **剔除**：忽略纯构建脚本、依赖升级（如 `bump version`）、格式化代码等对用户无感知的变动。
   - **剔除**：忽略极其笼统的描述，如“修复了一些bug”、“优化代码”、“update”、“misc fix”，除非能从上下文中推断出具体内容。

2. **语义聚合 (Aggregation)**：

   - **合并**：如果多个 commit 都在修改同一个功能（例如“新增波形图”、“修复波形图bug”、“调整波形图颜色”），请将它们合并为一条最终的、完整的描述（例如“新增音频波形图可视化功能，并优化了渲染性能”）。
   - **去重**：如果一个 bug 被多次尝试修复，只保留最终修复的结果。

3. **类别纠正**

   纠正一些明显的分类错误，比如实际上时修复bug但错误的以`feat:`开头

1. **分类与排序 (Categorization & Sorting)**：

   - 请将整理后的条目分为三类：**新功能 (New Features)**、**重构 (Improvements)**、**修复 (Bug Fixes)**。
   - **优先级排序**：
     - 第一梯队：用户直接可见的界面变化、交互改进、显著的性能提升。
     - 第二梯队：核心逻辑调整、准确率提升。
     - 第三梯队：底层技术细节（仅保留极重要的）。

2. **文案风格 (Style)**：

   - **简洁精炼**：每条记录不超过一句话。
   - **用户导向**：避免使用晦涩的变量名或纯技术术语（如 "Fix KeyError in utils.py"），转化为用户能懂的描述（如 "修复了特定情况下处理长视频失败的问题"）。
   - **拒绝废话**：不要写“我们要让软件更好”之类的空话。
   - 需要生成两种不同的格式，格式一如下：

   ```
   修复：\n- 修复了Whisper幻觉问题\n- 优化了波形渲染速度
   ```

   格式二采用github release标准的markdown格式，不使用emoji和图标

# Output Format

请分两步输出：
1. **中文更新日志**：按照上述规则生成的最终版本。
2. **英文更新日志 (English Version)**：对应中文的准确翻译，保持专业术语（如 VRAM, CUDA）不变。
