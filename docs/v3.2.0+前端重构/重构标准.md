## 1. 技术架构

### 1.1 技术栈

| 层级         | 当前                 | 目标                | 迁移策略          |
| ------------ | -------------------- | ------------------- | ----------------- |
| **布局**     | SCSS 手写            | Tailwind CSS        | 逐步替换          |
| **主题**     | SCSS 变量 + CSS 变量 | 纯 JS Design Tokens | 新建系统 + 兼容层 |
| **组件库**   | Element Plus         | Element Plus        | 不变              |
| **颜色**     | 混合使用             | CSS Variables 统一  | 全面迁移          |
| **预处理器** | SCSS                 | 不使用              | 逐步移除          |

### 1.2 目录结构

```
frontend/src/
├── theme/                          # 主题系统（纯 JS）
│   ├── index.js                    # 导出入口
│   ├── tokens/                     # 设计令牌
│   │   ├── base.js                 # 基础令牌（圆角、阴影等）
│   │   ├── dark.js                 # 深色主题
│   │   ├── light.js                # 浅色主题（预留）
│   │   └── index.js                # 主题注册表
│   ├── composables/
│   │   └── useTheme.js             # 主题切换逻辑
│   └── utils/
│       └── inject.js               # CSS 变量注入
├── styles/
│   ├── base.css                    # 基础样式（重置、字体等）
│   ├── tailwind.css                # Tailwind 入口
│   ├── element-override.css        # Element Plus 样式覆盖
│   ├── utilities.css               # 工具类（过渡期保留）

│       └── _mixins.scss            # 旧 mixin（保留供参考）
└── main.js
```

### 1.4 样式优先级规则

```
1️⃣ Tailwind 工具类 (最高优先级)
   └─ 布局、间距、尺寸、基础状态
   └─ 示例: tw-flex tw-gap-4 tw-p-4 tw-rounded-md

2️⃣ CSS Variables (通过 Tailwind 或直接使用)
   └─ 所有颜色、主题相关值
   └─ 示例: tw-bg-bg-primary 或 var(--af-bg-primary)

3️⃣ Scoped CSS (最低优先级，仅限特殊场景)
   └─ 复杂动画、:deep() 穿透、复杂选择器
   └─ 必须添加注释说明原因
```

## 2. 规则体系

### 2.1 强制性规则 🚫

> **这些规则必须严格遵守，违反将导致代码审查不通过**

---

#### 规则 R1：样式完整迁移原则 ⭐

**优先级**: 🔴 最高

**核心原则**：迁移过程中必须将原有样式100%完整迁移，**绝对不允许丢失任何样式细节**。为让重构前后的样式完全一致，**允许新增全局样式**，但必须标注清楚为谁使用

| 要求     | 状态        | 说明                          |
| -------- | ----------- | ----------------------------- |
| 样式完整 | ✅ 必须保留 | 所有视觉效果、交互效果不变    |
| 像素精确 | ✅ 必须保留 | 尺寸、间距、边框等数值不变    |
| 动画效果 | ✅ 必须保留 | 过渡动画、关键帧动画不变      |
| 响应式   | ✅ 必须保留 | 断点行为、媒体查询效果不变    |
| 伪类状态 | ✅ 必须保留 | hover、focus、active 效果不变 |

**样式冲突处理**：

| 情况               | 处理方式                 |
| ------------------ | ------------------------ |
| 新旧样式无冲突     | 直接迁移                 |
| 发现样式冲突       | ⚠️ **暂停并报告给用户**  |
| 用户确认后方可继续 | 记录决策并执行           |
| 不确定是否有冲突   | 保守处理，优先保留原样式 |

**检查清单**：

```
迁移前后对比检查：
□ 背景色、边框色、文字色是否一致
□ 字体大小、行高、字重是否一致
□ 内外边距、宽高是否一致
□ 圆角、阴影效果是否一致
□ hover/focus/active 状态效果是否一致
□ 动画过渡效果是否一致
□ 响应式断点行为是否一致
```

---

#### 规则 R2：禁止使用任何 SCSS 特性

**适用范围**：所有已完成迁移的 Vue 组件

| SCSS 特性                           | 状态        | 替代方案                         |
| ----------------------------------- | ----------- | -------------------------------- |
| SCSS 变量 (`$variable`)             | ❌ 完全禁止 | CSS Variables (`var(--af-*)`)    |
| SCSS 嵌套 (`&` 选择器)              | ❌ 完全禁止 | 展平选择器或使用 PostCSS         |
| SCSS 函数 (`darken()`, `lighten()`) | ❌ 完全禁止 | CSS `color-mix()` 或预定义变量   |
| SCSS Mixins (`@mixin`, `@include`)  | ❌ 完全禁止 | Tailwind 工具类或 CSS 自定义属性 |
| SCSS 运算 (`$size * 2`)             | ❌ 完全禁止 | CSS `calc()`                     |
| SCSS 导入 (`@import`)               | ❌ 完全禁止 | CSS `@import` 或 ES6 import      |

**检查方法**：

```bash
# 检查是否使用 SCSS 变量
grep -r '\$[a-zA-Z]' frontend/src/components/**/*.vue

# 检查是否使用 SCSS 嵌套
grep -r '&:' frontend/src/components/**/*.vue

# 检查是否使用 SCSS 函数
grep -rE '(darken|lighten|saturate|desaturate|mix)\(' frontend/src/components/**/*.vue
```

**违规示例**：

```vue
<!-- ❌ 错误：使用 SCSS 变量 -->
<style lang="scss" scoped>
$header-height: 56px;
.header {
  height: $header-height;
}
</style>

<!-- ✅ 正确：使用 CSS Variables -->
<style scoped>
.header {
  --header-height: 56px;
  height: var(--header-height);
}
</style>
```

---

#### 规则 R3：禁止混用 scoped 和非 scoped 样式块

**适用范围**：所有 Vue 组件

**核心原则**：一个组件文件只能有一个 `<style scoped>` 块，不得出现无 `scoped` 的 `<style>` 块。

| 模式                    | 状态        | 说明             |
| ----------------------- | ----------- | ---------------- |
| 单个 `<style scoped>`   | ✅ 允许     | 标准模式         |
| 多个 `<style scoped>`   | ⚠️ 不推荐   | 应合并为一个     |
| `<style>` (无 scoped)   | ❌ 禁止     | 污染全局命名空间 |
| 混用 scoped 和非 scoped | ❌ 严格禁止 | 违反样式隔离原则 |

**全局样式的正确位置**：

| 样式类型          | 正确位置                          | 示例                                |
| ----------------- | --------------------------------- | ----------------------------------- |
| Element Plus 覆盖 | `src/styles/element-override.css` | `:root { --el-color-primary: ... }` |
| 全局工具类        | `src/styles/utilities.css`        | `.text-ellipsis { ... }`            |
| 基础样式          | `src/styles/base.css`             | `body { ... }`                      |
| 第三方库覆盖      | `src/styles/vendor-override.css`  | `.some-lib { ... }`                 |

**检查方法**：

```bash
# 检查是否存在无 scoped 的 style 块
grep -rn '<style lang="scss">' frontend/src/components/**/*.vue | grep -v scoped

# 检查是否混用
awk '/<style/ {count++} END {if(count>1) print FILENAME " has multiple style blocks"}' frontend/src/components/**/*.vue
```

**违规示例**：

```vue
<!-- ❌ 错误：混用 scoped 和非 scoped -->
<template>...</template>

<style scoped>
.my-component { ... }
</style>

<style>
/* 全局样式，污染命名空间！ */
.el-button {
  background: red;
}
</style>
```

**正确做法**：

```vue
<!-- ✅ 方案 A：使用 :deep() -->
<style scoped>
.my-component { ... }

:deep(.el-button) {
  background: var(--af-accent-primary);
}
</style>

<!-- ✅ 方案 B：移到全局样式文件 -->
<!-- src/styles/element-override.css -->
.el-button { background: var(--af-accent-primary); }
```

---

#### 规则 R4：禁止硬编码颜色

**原则**：所有颜色必须使用 CSS Variables，不得使用 Hex、RGB、HSL 等硬编码值。

| 颜色格式                      | 状态        | 替代方案                                  |
| ----------------------------- | ----------- | ----------------------------------------- |
| Hex (`#ffffff`)               | ❌ 禁止     | `var(--af-bg-primary)`                    |
| RGB (`rgb(255, 255, 255)`)    | ❌ 禁止     | `var(--af-text-normal)`                   |
| RGBA (`rgba(0, 0, 0, 0.5)`)   | ⚠️ 特殊情况 | `rgba(var(--af-accent-primary-rgb), 0.5)` |
| HSL (`hsl(0, 0%, 100%)`)      | ❌ 禁止     | `var(--af-bg-primary)`                    |
| 颜色关键字 (`white`, `black`) | ❌ 禁止     | `var(--af-text-primary)`                  |

**特殊情况：透明度**

当需要动态透明度时，使用 RGB 变量：

```css
/* ✅ 正确：使用 RGB 变量 + 动态透明度 */
.overlay {
  background: rgba(var(--af-accent-primary-rgb), 0.3);
}

/* ❌ 错误：硬编码 RGBA */
.overlay {
  background: rgba(88, 166, 255, 0.3);
}
```

### 2.2 条件性规则 ⚠️

> **这些规则在特定条件下可以例外，但需要添加注释说明原因**

---

#### 规则 R5：非必须禁止使用 :deep()

**原则**：`:deep()` 是样式穿透的最后手段，应尽量避免使用。

**允许使用的场景**：

| 场景                      | 是否允许 | 条件                               |
| ------------------------- | -------- | ---------------------------------- |
| Element Plus 组件样式覆盖 | ✅ 允许  | 官方 CSS 变量无法满足需求          |
| 第三方库组件覆盖          | ✅ 允许  | 无其他方式修改样式                 |
| 动态插入的 DOM            | ✅ 允许  | 如富文本编辑器内容                 |
| 子组件内部样式            | ❌ 禁止  | 应通过 Props 或 CSS Variables 传递 |
| 覆盖自己的子组件          | ❌ 禁止  | 直接在子组件中修改                 |

**使用 :deep() 的正确姿势**：

```vue
<style scoped>
/* ✅ 正确：针对特定组件，添加注释说明原因 */
.my-dialog :deep(.el-dialog__header) {
  /* 原因：Element Plus 不提供 header 背景色的 CSS 变量 */
  background: var(--af-bg-secondary);
}

/* ❌ 错误：过度使用，应该用 CSS 变量 */
.my-button :deep(.el-button) {
  background: red; /* 应该用 --el-button-bg-color */
}

/* ❌ 错误：穿透自己的子组件 */
.parent :deep(.my-child-component) {
  /* 应该在 MyChildComponent.vue 中直接修改 */
  color: blue;
}
</style>
```

**检查方法**：

```bash
# 统计 :deep() 使用次数
grep -rn ':deep(' frontend/src/components/**/*.vue | wc -l

# 查看所有 :deep() 使用位置
grep -rn ':deep(' frontend/src/components/**/*.vue
```

**目标值**：每个组件 `:deep()` 使用次数 ≤ 3

### 2.3 代码质量规则 📋

> **这些规则确保代码质量和可维护性**

---

#### 规则 R6：严格限制 !important 使用

**原则**：`!important` 是样式优先级问题的症状，不是解决方案。

**目标值**：每个组件 `!important` 使用次数 ≤ 1

**允许使用的场景**：

| 场景                 | 是否允许    | 替代方案                        |
| -------------------- | ----------- | ------------------------------- |
| 覆盖第三方库内联样式 | ✅ 允许     | 无其他方式                      |
| 覆盖 Element Plus    | ❌ 禁止     | 使用 CSS 变量或提高选择器优先级 |
| 覆盖自己的样式       | ❌ 禁止     | 重构选择器结构                  |
| 工具类               | ⚠️ 谨慎使用 | 仅在 `utilities.css` 中         |

**正确的优先级提升方法**：

```css
/* ❌ 错误：使用 !important */
.button {
  background: red !important;
}

/* ✅ 方案 A：提高选择器优先级 */
.my-component .button {
  background: var(--af-accent-danger);
}

/* ✅ 方案 B：使用 CSS 层级 */
@layer components {
  .button {
    background: var(--af-accent-danger);
  }
}

/* ✅ 方案 C：使用 Element Plus CSS 变量 */
.my-component {
  --el-button-bg-color: var(--af-accent-danger);
}
```

## 3. 命名规范

### 3.1 CSS Variables 命名

```
格式: --af-{category}-{name}[-{variant}]

category:
  bg       - 背景色
  text     - 文本色
  accent   - 强调色
  border   - 边框
  shadow   - 阴影
  radius   - 圆角
  stage    - 阶段标记
  status   - 状态
  waveform - 波形专用
  video    - 视频专用

示例:
  --af-bg-primary
  --af-text-muted
  --af-accent-primary-hover
  --af-stage-whisper
```

### 3.2 CSS 类名（保留原有 BEM 风格）

```
保留原有类名，添加 Tailwind 类：

原来: <div class="subtitle-item">
现在: <div class="subtitle-item tw-flex tw-gap-4">

注意：不要删除原有类名，它们可能被 JS 引用或用于测试
```

### 4.2 详细步骤说明

#### Step 1: 全局检查

**目的**：识别目标文件中所有违反规则的样式代码

**检查项**：

```bash
# 1. 检查 SCSS 变量
grep -n '\$[a-zA-Z]' <文件路径>

# 2. 检查 SCSS 嵌套
grep -n '&:' <文件路径>

# 3. 检查硬编码颜色
grep -nE '#[0-9a-fA-F]{3,8}|rgb\(|rgba\(|hsl\(' <文件路径>

# 4. 检查 !important
grep -n '!important' <文件路径>

# 5. 检查 lang="scss"
grep -n 'lang="scss"' <文件路径>

# 6. 检查无 scoped 的 style
grep -n '<style>' <文件路径> | grep -v scoped
```

**输出**：违规列表，包含行号和违规类型

---

#### Step 2: 逐个修复

**原则**：

- 按照规则优先级顺序修复（R1 → R6）
- 每次修复后立即验证样式效果
- **关键**：确保原样式100%迁移，不丢失任何细节
- 发现冲突立即报告用户

**修复清单模板**：

```markdown
- [ ] 移除 lang="scss"，改为纯 CSS
- [ ] 将 SCSS 变量替换为 CSS Variables
- [ ] 展平 SCSS 嵌套选择器
- [ ] 将硬编码颜色替换为 CSS Variables
- [ ] 移除不必要的 !important
- [ ] 检查 :deep() 使用是否合理
```

---

#### Step 3: Stylelint 检查

**命令**：

```bash
cd frontend
npx stylelint "src/**/*.{vue,css}"
```

**预期输出**：所有报错和警告列表

---

#### Step 4: 修复 Stylelint 问题

**原则**：

- 先使用 Stylelint 自动修复，然后检查结果，手动修复剩下的部分
- 优先修复 error 级别问题
- 然后修复 warning 级别问题
- 每次修复后重新运行检查

**循环直到**：`0 errors, 0 warnings`

---

#### Step 5: 编译验证

**命令**：

```bash
cd frontend
npm run build
```

**预期输出**：编译成功，无错误

---

#### Step 6: 暂停等待用户检查

**说明**：

⏸️ **在此步骤暂停**

通知用户进行以下检查：

1. 启动开发服务器 (`npm run dev`)
2. 在浏览器中打开相关页面
3. 对比迁移前后的视觉效果
4. 检查所有交互状态（hover、focus、active）
5. 检查响应式布局

**用户反馈选项**：

- ✅ 通过：继续执行 Step 7
- ❌ 发现问题：返回 Step 2 修复

---

#### Step 7: 自动格式化

**前提**：用户确认通过后执行

**命令**：

```bash
cd frontend
npx stylelint "src/**/*.{vue,css}" --fix
```

border-color: rgb(var(--af-accent-success-rgb), 0.5)
